2027 教材的核心为 I/O 接口，以及程序查询、程序中断、DMA 三种方式。系统概述和外设指标用于建立背景；通道保留为原笔记的补充理解。

## 第一部分：I/O 系统要解决什么

### 1.1 先把四个角色分清

| 部件 | 主要职责 | 不能混淆的地方 |
|---|---|---|
| CPU | 执行程序、发命令、处理中断、设置传输 | DMA 时不必逐字搬数据 |
| 主存 | 存放程序和输入输出缓冲数据 | 设备通常不能随意访问任何位置 |
| I/O 接口/控制器 | 协调主机与设备，保存状态、命令和缓冲数据 | 接口不是设备本身 |
| 外部设备 | 实际输入、输出或存储信息 | 键盘、显示器、磁盘的工作方式不同 |

例如输入一个字符：键盘产生信息，接口暂存信息并表示“就绪”，CPU 或相关控制器再将数据送到后续位置。

### 1.2 为什么需要接口

CPU 与外设通常有三类差异：

- 速度不同：CPU 的执行节拍与设备产生数据的时间不同。
- 格式不同：主机可能并行传字，设备可能串行传位。
- 信号和操作不同：设备需要专门控制命令，电气条件也可能不同。

接口通过缓冲、转换和控制，建立双方能够遵循的交换过程。缓冲能吸收短时速度差异，但容量有限，不能无限保存设备持续产生的数据。

### 1.3 三种控制方式围绕两个问题比较

第一个问题：谁发现设备已经就绪？

- 查询：CPU 主动反复读取状态。
- 中断：设备就绪后发请求，CPU 到适当时机响应。
- DMA：控制器接收设备传输请求并协调数据传输，CPU 通常在整块结束后收到通知。

第二个问题：谁搬运每份数据？

- 查询和程序中断：通常由 CPU 执行指令搬运。
- DMA：正常数据传送阶段由硬件控制器直接协调主存与设备间的搬运。

**中断主要减少主动等待，DMA 还减少 CPU 逐项搬运数据的工作。**

## 第二部分：I/O 接口与端口

### 2.1 接口的基本功能

接口需要完成：地址译码和设备选择、数据缓冲、控制与状态管理、信号或格式转换，以及主机和设备间的通信协调。

CPU 发出一个端口地址时，地址译码电路判断是否选中本接口中的某个寄存器。控制逻辑再依据读写信号确定本次操作。

因此 CPU 并非只发一个“设备名字”，而是通过地址和控制信号访问规定的接口资源。

### 2.2 数据、状态、控制寄存器分别存什么

| 寄存器 | 存放内容 | CPU 的典型操作 |
|---|---|---|
| 数据寄存器 | 输入数据或待输出数据 | 读输入数据；写输出数据 |
| 状态寄存器 | 就绪、忙、完成、错误等状态 | 读取并判断状态位 |
| 控制寄存器 | 启动、停止、方向、模式等命令 | 写入控制字 |

输入设备：设备把数据放到接口的数据寄存器，同时置就绪状态；CPU 确认就绪后读取数据。

输出设备：CPU 确认设备可接收，再把待输出数据写入接口，接口控制设备完成输出。

### 2.3 接口、端口、端口地址不是同一件事

接口是连接和控制电路的整体；I/O 端口是其中可由 CPU 访问的寄存器；端口地址是访问这个寄存器所使用的编号。

一个接口可以有多个端口，一个设备不一定只有一个端口。比如一个接口可以分别有数据、状态、控制三个端口。

教材还允许状态与控制共用一个端口地址：读该地址取得状态，写该地址下达命令。地址相同并不表示读写含义相同。

### 2.4 状态位怎样控制传输

假设状态寄存器 bit0 为 READY，1 表示输入数据已经准备好：

```text
读状态 → 检查 READY
READY=0：继续等待或稍后再查
READY=1：读取数据寄存器
```

具体设备可能规定读取数据后自动清 READY，也可能需要另外确认。做题按给定协议分析，不凭经验假设状态一定自动改变。

### 2.5 CPU 在接口中读取的，不只有业务数据

数据总线还可能承载状态字、控制字和中断类型号等。地址总线指出访问哪个端口，控制线说明本次是读还是写。

所以“状态通过控制总线整字返回”通常是不准确的基本理解：控制线协调操作，状态寄存器的内容通常通过数据通路被读取。

## 第三部分：统一编址与独立编址

### 3.1 统一编址把端口纳入主存地址空间

主存单元和 I/O 端口使用同一套地址空间。某些地址分配给主存，某些地址分配给 I/O。

例如：

```text
0x0000～0xEFFF：分配给存储器
0xF000：输入数据端口
0xF004：状态端口
0xF008：控制端口
```

CPU 可使用相应访存指令访问这些端口。译码电路根据地址范围区分目标。

这里“把端口当作存储单元访问”是地址与指令层面的安排，不意味着外设寄存器就是普通 RAM。

### 3.2 独立编址使用单独的 I/O 地址空间

主存地址和 I/O 地址分别编号。I/O 端口 0x20 与主存地址 0x20 可以同时存在，因为它们属于不同空间。

CPU 通过专门 I/O 指令和相应控制信号说明自己要访问 I/O。例如 x86 的 IN、OUT 属于这类指令。

判断是否冲突时，不能只比较地址数值，还要比较地址空间。

### 3.3 两种编址方式的比较

| 项目 | 统一编址 | 独立编址 |
|---|---|---|
| 地址空间 | 与主存共用 | 与主存分开 |
| 使用指令 | 相应访存指令 | 专门 I/O 指令 |
| 地址占用 | 占用可分配的主存地址空间 | 不占主存地址空间 |
| 程序访问 | 可利用相应访存寻址方式 | 受 I/O 指令能力约束 |
| 区分方法 | 地址范围等译码 | 指令及 I/O 控制信号等 |

统一编址“占主存地址空间”不等于额外消耗同容量的物理 RAM 芯片。它首先限制的是哪些地址可以分配给主存。

### 3.4 例题：16 位统一地址空间预留 256 个字节地址

按字节编址，共有：

$$
2^{16}=65536\text{ 个地址}
$$

若其中 256 个地址保留给 I/O，剩余最多可分配给主存的字节地址数量：

$$
65536-256=65280
$$

因此在这个简化映射下，主存最多占 65280 B。若改为独立编址，I/O 的这些端口不会占用这 65536 个主存地址。

## 第四部分：程序查询怎样传数据

### 4.1 CPU 一边查状态，一边负责搬运

以输入 $N$ 个数据为例：

1. 设置主存缓冲区起点和剩余数量 $N$。
2. 向接口发启动命令。
3. 读取状态端口。
4. 未就绪则继续查询，或按安排稍后查询。
5. 已就绪则读取数据端口，将数据写到缓冲区。
6. 修改主存地址、减少剩余数量。
7. 未完成则返回查询；完成则结束。

```text
设备 → 接口数据寄存器 → CPU 寄存器 → 主存缓冲区
```

上面每次搬运都由 CPU 的程序控制，这是查询方式的重要特点。

### 4.2 独占忙等与定时查询不能用同一种占比解释

独占忙等：CPU 在设备未就绪时持续执行查询循环，期间可能几乎没有时间做其他工作。

定时查询：CPU 每隔一段时间查询一次，其他时间执行其他程序或任务。

公式“每秒查询次数 × 每次查询周期数”计算的是给定查询安排的开销。它不能自动代表一个不停忙等的程序实际占用 CPU 的全部时间。

### 4.3 缓冲单位决定最低服务频率

设设备持续输入数据率为 $R$ B/s，接口每次可交付 $u$ B，且缓冲只能容纳这样一份未读数据。

相邻数据到达间隔为：

$$
\Delta t=\frac{u}{R}
$$

理想化最低服务次数约为：

$$
\lambda=\frac{R}{u}
$$

要避免覆盖，必须在缓冲被下一份数据占用前完成读取。实际还要计入查询相位、读取耗时和时间余量；仅让平均查询频率等于 $R/u$，并不能在任意相位和延迟下保证不丢数据。

### 4.4 例题：1 MB/s、每次 1 B、查询一次 20 周期

设 MB 使用十进制，设备数据率 $R=10^6$ B/s，每次处理 1 B，CPU 主频 2 GHz。按每份数据安排一次查询，每次仅计查询部分的 20 个周期。

每秒查询次数：

$$
\lambda=10^6/1=10^6
$$

查询消耗：

$$
C=10^6\times20=2\times10^7\text{ 周期/s}
$$

CPU 查询开销比例：

$$
P=\frac{2\times10^7}{2\times10^9}=1\%
$$

**1% 是上述查询安排的周期预算。**它没有包含搬数据、修改地址、循环和等待等其他开销。如果程序独占 CPU 不停地查状态，就不能据此说其 CPU 实际占用率只有 1%。

### 4.5 判断查询方式是否来得及

如果每份数据的查询加搬运共需 $C_s$ 个 CPU 周期，则理想化每秒需求为：

$$
C_{\mathrm{need}}=\frac{R}{u}C_s
$$

若 $C_{\mathrm{need}}>f$，即需求超过 CPU 每秒可提供的周期，即使 CPU 全部用于服务设备也无法满足。

即便平均需求低于主频，还需检查单份数据的截止时间和缓冲容量。平均开销可接受与每次都及时响应是两个条件。

## 第五部分：中断请求与响应

### 5.1 中断让设备主动通知 CPU

CPU 启动外设后可以继续执行原程序。设备准备好或完成操作时，通过接口发出中断请求。CPU 响应后执行中断服务程序，再返回原程序。

```text
原程序运行 → 设备提出请求 → CPU 响应
    → 中断服务程序 → 返回原程序继续运行
```

“请求到达”与“开始执行服务程序”可能不是同一时刻，因为还要满足响应条件。

### 5.2 可屏蔽 I/O 中断的典型响应条件

在教材基本模型中，需要：

1. 中断源确实有请求。
2. CPU 允许可屏蔽中断，即开中断。
3. 该中断源未被屏蔽。
4. CPU 到达规定响应边界，通常为当前指令执行结束。

因此设备在指令执行中途提出请求时，CPU 通常先完成当前指令，再判断并响应。

这些条件针对可屏蔽外部中断。第五章的异常、不可屏蔽中断等有不同触发和返回规则，不能直接套用同一描述。

### 5.3 关中断与屏蔽某个源的区别

关中断是暂时禁止 CPU 响应可屏蔽中断；屏蔽某个源是只禁止规定中断源通过筛选。

开中断以后仍可能不响应某个请求，因为它被屏蔽。反过来，某个源没有被屏蔽，若 CPU 仍关中断，也不能据此开始嵌套响应。

基本模型中，屏蔽影响响应资格，未响应的请求可保持为待处理状态。是否丢弃、合并重复请求，要看请求寄存器和设备协议，不能一律认为会逐个排队。

### 5.4 多个请求同时到达怎样选择

中断判优逻辑从当前有效且允许响应的请求中选出一个。选择可以由硬件优先逻辑完成，或由软件查询中断源完成。

硬件判优的先后次序称为响应优先级。它决定当前这一刻先响应谁；服务程序执行期间能否被另一个中断打断，还需要看屏蔽字与开中断状态。

### 5.5 中断隐指令不是程序中的普通指令

教材把 CPU 响应中断时由硬件完成的一组操作称为中断隐指令，通常概括为：

- 关中断，保护响应过程。
- 保存断点和体系结构规定的状态。
- 找到中断服务程序入口并转入执行。

“隐”表示它不需要原程序事先写一条普通机器指令来启动。它仍然需要硬件动作和执行时间。

## 第六部分：中断向量与服务过程

### 6.1 类型号、向量地址、中断向量分别是什么

中断类型号：用于区分中断来源或类别的编号。

向量地址：中断向量表中相应表项的存放地址。

中断向量：该表项保存的入口信息，教材基本解释为中断服务程序入口地址。

```text
类型号 n
   ↓ 计算表项地址
向量地址 = 表基址 + n × 表项大小
   ↓ 读取表项
中断向量 = 服务程序入口信息
   ↓
PC 转入服务程序
```

实际体系结构的表项可能包含不止一个地址字段，做题必须使用题目给出的格式。

### 6.2 例题：类型号 5，向量表基址 0x1000

若每项 4 B，类型号为 5，表项存放地址：

$$
0x1000+5\times4=0x1014
$$

假设该地址的表项内容为 0x8000，则：

- 类型号：5。
- 向量地址：0x1014。
- 中断服务程序入口：0x8000。

不能把 0x1014 直接写入 PC 当作服务入口；它在此题中只是入口地址的存放位置。

### 6.3 为什么既保存断点，又保护现场

断点说明返回后从哪条指令继续。现场说明原程序依赖的寄存器和状态是什么。

如果只保存 PC，中断服务程序把某寄存器改了，返回后原程序可能继续使用被修改的值而出错。

所以需要保护服务程序可能破坏的必要状态。哪些由硬件自动保存、哪些由软件保存，取决于体系结构和程序约定；不应把“所有寄存器硬件自动保存”当作通用规则。

### 6.4 单重中断的完整过程

```text
硬件响应：关中断 → 保存断点/规定状态 → 转服务入口
软件服务：保护必要现场 → 处理设备 → 恢复现场
返回：恢复规定状态和断点 → 从原程序继续
```

单重中断的服务期间不再接受新的可屏蔽中断。其他请求需等待当前服务完成并重新具备响应条件。

### 6.5 多重中断为何先保护现场，再开中断

典型嵌套过程：

1. 硬件响应并关中断。
2. 保存当前服务所需现场和原屏蔽字。
3. 设置本层服务的屏蔽字。
4. 开中断，允许规定的更高处理优先级请求嵌套。
5. 执行本层服务。
6. 结束前关中断，防止恢复到一半又被打断。
7. 恢复原现场、原屏蔽字及规定状态。
8. 中断返回。

如果未保护现场就开中断，嵌套服务可能破坏尚未保存的信息。返回时也必须恢复上一层状态，不能把最内层的屏蔽字一直留给外层。

### 6.6 中断返回与普通 RET 的区别

普通函数返回通常恢复返回地址，并遵守函数调用约定。中断返回还要恢复中断响应时保存的规定状态，如中断允许状态等。

所以中断服务程序的结束不能一般性地用普通 RET 替代。具体返回指令和自动恢复内容，由体系结构规定。

## 第七部分：多重中断、屏蔽字与执行轨迹

### 7.1 响应优先级与处理优先级为什么可以不同

响应优先级决定多个允许响应的请求同时存在时，判优电路先选谁。处理优先级决定某个服务程序运行期间，哪些其他中断可以打断它，可通过该服务程序设置的屏蔽字体现。

比如硬件响应顺序为 $A>B>C$，而要求处理顺序为 $C>A>B$。原程序中 A、B 同时请求，先响应 A；执行 A 服务时，如果允许 C 且 C 到达，就可以由 C 嵌套打断 A。

不要把两个“优先级”默认写成同一顺序。

### 7.2 写屏蔽表前，先声明 0 和 1 的含义

本节规定：**1 表示屏蔽，0 表示允许响应。**列表示请求来自谁，行表示当前正在服务谁。

要求处理优先级为 $C>A>B$，通常屏蔽本级和低于本级的请求，允许高于本级的请求：

| 正在服务 | 请求 A | 请求 B | 请求 C | 解释 |
|---|---|---|---|---|
| A | 1 | 1 | 0 | 自身及 B 被屏蔽，只允许 C 嵌套 |
| B | 0 | 1 | 0 | 允许 A、C，屏蔽 B 自身 |
| C | 1 | 1 | 1 | 最高处理优先级，屏蔽全部这三类 |

这张表只针对可屏蔽请求。即使某列为 0，CPU 也要处于开中断状态并到达允许的响应边界，才会实际嵌套。

### 7.3 一行一行写，避免把表转置

例如正在服务 A：先判断 A 能否打断自己，本题不允许，A 列写 1；B 比 A 低，B 列写 1；C 比 A 高，C 列写 0。得到 A 行 110。

再处理 B：A、C 都高于 B，所以 B 行 010。C 最高，C 行 111。

如果题目规定 1 表示允许，则需要将这些逻辑值对应转换。不能不看编码定义直接背 110、010、111。

### 7.4 完整时间线：先响应 A，再由 C 打断

题设：

- 响应优先级 $A>B>C$；处理优先级 $C>A>B$。
- A、B 在 $t=0$ 同时请求。
- C 在 $t=2\ \mu s$ 请求。
- A 服务需 10 μs，B 需 2 μs，C 需 3 μs。
- 为便于观察，响应、保护和恢复开销忽略，嵌套条件均已满足；未响应的请求保留。

逐步处理：

1. $t=0$，A、B 都待处理，按响应优先级选 A。B 继续等待。
2. $t=0$ 到 2，A 已服务 2 μs，尚需 8 μs。
3. $t=2$，C 到达，A 的屏蔽字允许 C，因此转入 C。
4. $t=2$ 到 5，完成 C 的 3 μs。B 仍不能打断 C。
5. $t=5$，返回 A 的断点，继续剩余 8 μs，到 $t=13$ 完成 A。
6. $t=13$，返回原程序后处理仍待处理的 B，到 $t=15$ 完成。

```text
时间/μs   0         2             5                      13     15
CPU       |-- A ----|---- C -------|-------- A ------------|-- B --|
A进度     已做2μs      暂停                再做8μs
B请求     一直保留，等待具备响应机会
```

核对总服务时间：$10+3+2=15$ μs。A 被打断后继续剩余部分，不能回头把完整 10 μs 再算一遍。

### 7.5 画执行轨迹的固定方法

列出每个中断的到达时刻、需要的服务时间、剩余时间和当前是否被屏蔽。每个新事件到达时依次判断：

1. 当前是否在可响应状态？
2. 新请求是否通过当前屏蔽字？
3. 多个有效请求中先响应谁？
4. 若嵌套，当前程序剩余多少服务时间？
5. 返回时应该恢复哪一层现场和屏蔽字？

可以把现场理解成后进先出的栈：最内层完成后，先回到刚刚被它打断的那一层。

### 7.6 屏蔽不等于请求已经处理

被屏蔽的请求在基本请求保持模型里仍然待处理。恢复允许状态后，CPU 还需对这些请求进行判优。

“未嵌套”也不等于“请求消失”。画时间线时，应将它保留到后续可响应时刻。题目若另有请求清除规则，再按该规则修改。

## 第八部分：程序中断的开销怎样算

### 8.1 数据率先转换成每秒中断次数

若设备持续数据率为 $R$ B/s，每次中断处理 $B_i$ B，则理想化稳定条件下：

$$
\lambda_i=\frac{R}{B_i}\quad\text{次/s}
$$

若每次中断消耗 $C_i$ 个 CPU 周期，且已经包含题目指定的响应、保护、传输、恢复等开销：

$$
\boxed{P_{\mathrm{CPU}}=\frac{R}{B_i}\frac{C_i}{f}}
$$

公式只统计给定的 CPU 周期开销。设备自身等待时间、DMA 总线时间等不应未经说明全部加到中断服务的 CPU 周期里。

### 8.2 例题：10 MB/s，每次中断处理 1 KiB

数据率 10 MB/s 使用十进制，即 $10^7$ B/s；一块 1 KiB 为 1024 B。

每秒中断次数：

$$
\lambda_i=\frac{10^7}{1024}=9765.625\text{ 次/s}
$$

设每次 2000 周期，CPU 2 GHz：

$$
P=\frac{9765.625\times2000}{2\times10^9}
=0.009765625\approx0.9766\%
$$

这里的小数次数表示长期平均频率；若题目问一次有限长度传输要多少次中断，最后不足一块可能也需一次通知，应根据传输规则向上取整。

### 8.3 为什么每字节中断可能来不及

仍取 10 MB/s、每次 2000 周期、CPU 2 GHz，若改为每 1 B 就中断一次：

$$
P=\frac{10^7\times2000}{2\times10^9}=10=1000\%
$$

这不是说 CPU 可以达到 1000% 的物理使用率，而是说需求相当于当前 CPU 可用能力的十倍，方案无法持续满足设备速度。

通过缓冲把多个字节合成一次服务，可以分摊每次响应和保存恢复的固定开销。增加缓冲也会影响通知延迟，题目可能要求兼顾及时性。

### 8.4 多个设备的开销怎样合计

若各设备每秒中断次数为 $\lambda_j$，每次占用 $C_j$ 周期，理想化总占比：

$$
P_{\mathrm{total}}=\frac{\sum_j\lambda_jC_j}{f}
$$

要避免重复统计：若 $C_j$ 已包含响应和返回，不要再次额外添加同一部分。

若占比接近或超过 1，普通计算任务将缺乏周期预算，甚至连 I/O 都服务不过来。即便占比低，也仍要检查高优先级服务是否让低优先级设备错过期限。

## 第九部分：DMA 的组成与完整过程

### 9.1 DMA 为什么减少 CPU 的搬运工作

查询与程序中断中，数据通常通过 CPU 执行的读写指令转移。DMA 数据传送阶段由控制器协调设备和主存之间的数据通路，不必让 CPU 对每个字都执行搬运指令。

```text
CPU：设置任务、继续执行其他程序、处理结束通知
DMA：按设置取数据/写数据、更新地址、减少计数
数据：设备 ⇄ 主存
```

“直接”是指正常传输不由 CPU 逐项搬运，不是没有总线、地址、控制或权限约束。

### 9.2 DMA 控制器中的关键部件

| 部件 | 功能 | 每次成功传输后的典型变化 |
|---|---|---|
| 主存地址寄存器 | 记录当前主存位置 | 加一个传输单位的地址增量 |
| 长度/字数计数器 | 记录还需传多少 | 减一个传输单位 |
| 数据缓冲寄存器 | 暂存本次传送数据 | 放入或送出下一份数据 |
| 控制与状态逻辑 | 方向、模式、请求、完成、错误 | 根据阶段更新状态 |
| 请求与总线控制逻辑 | 申请并取得总线使用权 | 传输后按模式释放或继续 |
| 完成通知逻辑 | 整块结束后通知 CPU | 发完成中断等 |

地址增量不能固定背“加 1”：若按字节编址、每次传 4 B，地址通常加 4；若按字编址、每次传一个字，通常加 1。

### 9.3 预处理：CPU 把任务说清楚

CPU 通过程序设置：传输方向、主存缓冲区起点、设备或外存相关位置、传输长度、工作方式，并启动传输。

CPU 必须先安排有效的缓冲区。DMA 控制器只根据给定参数行动，不能自行猜出程序希望保存到哪个数组。

完成这些设置后，CPU 通常可继续执行其他工作。

### 9.4 数据传送：控制器循环执行

基本过程：

1. 设备准备好数据或准备接收数据。
2. DMA 控制器收到请求，申请总线或主存访问机会。
3. 在规定的安全边界获得使用权。
4. 给出地址和读写控制，完成一份数据传输。
5. 修改地址、计数等参数。
6. 若未完成，继续或等待下一次设备请求。
7. 若完成，释放相应资源，产生完成状态和通知。

传送每个字与通知整块结束是两个层次。一次整块 DMA 可以包含很多次总线数据拍，但只在整块完成时需要一次完成中断。

### 9.5 后处理：CPU 确认结果并收尾

整块传输结束后，控制器通常通过中断通知 CPU。CPU 检查完成状态、错误和已传长度，并进行必要的后续处理。

因此 DMA 仍可使用中断。不能把“DMA 与中断”理解成二者绝不共同出现。

DMA 与程序中断的区别在于**数据传送阶段由谁执行**，以及通知和 CPU 处理发生的频率。

### 9.6 DMA 请求和完成中断分别请求什么

DMA 请求是为了取得数据传输所需的总线或主存访问机会；完成中断是为了让 CPU 执行结束处理程序。

教材基本模型下，DMA 请求可在当前总线/存储周期的规定边界获准，不必等到整条 CPU 指令结束。可屏蔽程序中断通常在当前指令结束后响应。

DMA 获准不需要像中断服务那样必然切换到一段服务程序、保存整套程序现场。CPU 的访存可能被延迟，但它不是因为每个 DMA 字都进入一次服务程序。

## 第十部分：DMA 访存方式与性能

### 10.1 停止 CPU 访存：集中占用主存通路

DMA 一段时间内连续使用主存，CPU 暂时不能通过冲突的通路访问主存。

优点是连续传输控制较简单、启动与交接开销容易分摊；代价是 CPU 的访存可能被阻塞较长时间。

若 CPU 有不依赖这条通路的内部运算或可用 Cache，是否仍能推进部分工作要看系统结构。不能无条件推断“DMA 工作时 CPU 的所有部件完全停止”。

### 10.2 周期挪用：需要时取一个或若干存储周期

DMA 需要传数据时申请访问机会，传完后释放。CPU 和 DMA 按仲裁结果交替使用共享资源。

若 CPU 当前不需要主存，DMA 可利用空闲机会；若 CPU 也需要主存，DMA 的传输可能延迟 CPU 的访存。它挪用的是资源使用时间，不是让 CPU 丢失原程序断点。

相对集中占用，CPU 的延迟可以更分散，但每次申请和释放也可能带来开销。

### 10.3 DMA 与 CPU 交替访存：预先划分时段

系统可以把一个较长 CPU 周期内的访存时段分别安排给 CPU 和 DMA。双方按固定时段使用主存，不必每次都重新竞争。

适用前提是主存访问足够快且时序允许切分。固定分配使控制安排明确，但若某方没有请求，它的保留时段可能闲置。

把三种方式记成：连续占用、按需挪用、固定交替。

### 10.4 总线占用按数据拍算

设数据率 $R$ B/s，总线每拍传 $u$ B，每拍占 $c_b$ 个总线周期，总线时钟频率为 $f_b$：

$$
\lambda_b=\frac{R}{u},\qquad
P_{\mathrm{bus}}=\frac{R}{u}\frac{c_b}{f_b}
$$

若还有地址、等待、申请等开销，应计入各块或各事务的总时间。公式中的 $c_b$ 只有在题设明确相应开销已经包括或忽略时才能直接使用。

### 10.5 例题：200 MB/s 的 DMA 占多少总线时间

题设：设备数据率 200 MB/s，64 位总线，100 MHz，每传 8 B 占一个总线周期，忽略其他开销。

每秒数据拍数：

$$
\lambda_b=\frac{200\times10^6}{8}=25\times10^6\text{ 拍/s}
$$

总线每秒有 $100\times10^6$ 个周期，故：

$$
P_{\mathrm{bus}}=\frac{25\times10^6}{100\times10^6}=25\%
$$

**25% 是这组假设下的数据传送总线占比，不能直接当作 CPU 软件开销。**CPU 可能没有逐拍搬运，但它的主存访问可能受竞争影响。

### 10.6 CPU 开销按块的预处理与后处理算

设每块传 $B_d$ B，CPU 每块预处理与后处理共 $C_d$ 周期，主频为 $f$：

$$
\boxed{P_{\mathrm{CPU,DMA}}=\frac{R}{B_d}\frac{C_d}{f}}
$$

例如设备 40 MB/s，每块 1000 B，CPU 每块合计 500 周期，主频 500 MHz：

$$
\lambda_d=\frac{40\times10^6}{1000}=40000\text{ 块/s}
$$

$$
P=\frac{40000\times500}{500\times10^6}=4\%
$$

不要再把每个 DMA 数据拍当作 CPU 执行了一条搬运指令加进去。但如果题目问整个程序的运行时间，DMA 竞争造成的 CPU 等待也可能需要另行考虑。

### 10.7 DMA 与 Cache 一致性为什么需要协调

CPU 可能在 Cache 中保存某个主存缓冲区的旧副本。若 DMA 直接写主存，CPU 后续读到的 Cache 副本可能仍是旧数据。

反方向，CPU 刚修改的缓冲数据可能只在写回 Cache 中，尚未写入主存。DMA 从主存读取时就可能拿到旧数据。

解决思路是在交接前后保证相关数据一致，例如依靠硬件一致性，或按系统要求写回、失效相关 Cache 数据。是否需要软件操作取决于系统，不能说所有 DMA 都一定自动绕过问题，或都一定要求手工刷新。

### 10.8 把三种方式放到同一张表

| 项目 | 程序查询 | 程序中断 | DMA |
|---|---|---|---|
| 谁发现就绪 | CPU 主动查状态 | 设备/接口提出请求 | 设备与 DMA 控制器协调 |
| 谁搬正常数据 | CPU 执行指令 | CPU 执行服务程序中的指令 | 控制器硬件协调 |
| CPU 是否等待设备 | 忙等时持续等待；定时查询时可做别的工作 | 等待阶段可执行其他工作 | 传送阶段可执行其他工作，但可能竞争主存 |
| CPU 介入粒度 | 每次查询与搬运 | 每次中断服务 | 每块设置和收尾 |
| 主要开销 | 查询、搬运、循环 | 响应、保护恢复、搬运 | 控制器和总线开销、块级 CPU 开销 |
| 学习重点 | 服务频率与周期预算 | 响应条件、屏蔽、轨迹 | 组成、三阶段、访存与两种占比 |

选方式要看数据率、缓冲、传输量、及时性和硬件条件。DMA 的固定设置成本需要分摊，并非任何一两个字节的传输都必须采用 DMA。

## 第十一部分：补充——外设指标、通道与 I/O 处理机

### 11.1 显存容量从像素数量算起

若一帧有 $X\times Y$ 个像素，每个像素用 $b$ bit 表示颜色，则仅保存一帧像素数据所需容量：

$$
V=XY\frac{b}{8}\text{ B}
$$

例如 $1024\times1024$ 像素、256 种颜色，每个像素需要 $\log_2 256=8$ bit：

$$
V=1024\times1024\times1=2^{20}\text{ B}=1\text{ MiB}
$$

256 种颜色不是每个像素用 256 bit。先从颜色数量推出每个像素的编码位数。

### 11.2 刷新数据量与有效带宽

若每秒刷新 $F$ 帧，且简化为每帧读取完整像素数据一次，则：

$$
B_{\mathrm{frame}}=XY\frac{b}{8}F
$$

如果只有比例 $\eta$ 的显存带宽能用于刷新，则所需总带宽至少为：

$$
B_{\mathrm{total}}\ge\frac{B_{\mathrm{frame}}}{\eta}
$$

例：1600×1200、24 bit 色深、85 帧/s：

$$
B_{\mathrm{frame}}=1600\times1200\times3\times85
=489.6\times10^6\text{ B/s}
$$

若刷新只能使用 50% 带宽，则至少 979.2 MB/s。这是题设的像素模型，没有计入题目未指定的额外协议或多缓冲开销。外设指标属于本章参考背景，先保证单位计算正确。

### 11.3 通道在 DMA 基础上进一步承担控制

DMA 主要根据 CPU 设置的参数搬运数据。通道可执行通道程序，进一步管理一组 I/O 操作，例如设备选择、传输安排和操作顺序。

可以理解为 CPU 把更完整的 I/O 任务交给专门控制部件，使 CPU 减少逐项管理。

通道程序控制 I/O 任务，不等于普通 CPU 通用程序。它的指令和能力取决于通道设计。

### 11.4 三种通道的区别

| 类型 | 典型组织方式 | 适合怎样理解 |
|---|---|---|
| 字节多路通道 | 多个低速设备交叉传字节 | 一个设备暂未就绪时可服务另一个 |
| 选择通道 | 一段时间集中服务一个高速设备 | 以较长连续任务占用通道 |
| 数组多路通道 | 多个设备按块或数组轮换服务 | 兼顾块传输与多设备切换 |

I/O 处理机具有更独立、较强的处理能力，可进一步承担 I/O 管理。这里保留原笔记术语用于理解发展关系；2027 本章主线先学牢查询、中断和 DMA。

## 自测：先独立回答，再看解析

### 题目

1. 同一个接口有数据、状态、控制寄存器，它一定只占一个端口地址吗？
2. I/O 地址 0x20 与主存地址 0x20 数值相同，能否同时存在？
3. 2 GHz CPU，每秒定时查询 $10^6$ 次，每次 20 周期，查询开销是多少？可以推出持续忙等实际只占 1% CPU 吗？
4. 类型号 7，向量表基址 0x2000，每项 4 B，表项保存入口 0x9000。向量地址和服务入口分别是什么？
5. 处理优先级 $C>A>B$，1 为屏蔽，正在服务 B 时屏蔽字按 A、B、C 排列是多少？
6. 设备 10 MB/s，每次中断处理 1 KiB，共需 2000 周期，CPU 2 GHz，CPU 开销多少？
7. DMA 数据率 200 MB/s、64 位总线、100 MHz、每拍一周期，忽略额外开销，总线占比多少？这是 CPU 开销吗？
8. DMA 是否完全不需要 CPU？是否不能使用中断？
9. DMA 每次传 4 B，主存按字节编址，主存地址寄存器应如何变化？
10. CPU Cache 中有旧数据，DMA 已把新数据写到主存，CPU 后续读取会有什么问题？

### 解析

1. 不一定。一个接口可有多个端口地址，也可以按读写不同含义共用某些地址。
2. 独立编址时可以，它们属于不同空间；统一编址时同一普通地址必须根据映射和协议确定访问目标。
3. 查询开销为 1%；不能据此推出持续忙等实际只占 1%，它还有额外查询、等待、传输和循环等工作。
4. 向量地址 $0x2000+7\times4=0x201C$；服务入口为 0x9000。
5. 010：A、C 可打断 B，B 自身屏蔽。实际响应还须开中断等条件满足。
6. 每秒 $10^7/1024=9765.625$ 次，CPU 开销约 0.9766%。
7. 25%；这是数据传输总线占比，不是 CPU 软件开销。
8. CPU 通常负责预处理和后处理，整块完成可以通过中断通知 CPU。
9. 正常连续传输时加 4；不能因“传一个字”就不看编址单位而固定加 1。
10. CPU 可能命中旧 Cache 副本，需要按系统一致性机制保证交接后可见新数据。

## 学完后应能直接判断

- 中断到达不等于马上执行服务程序。
- 开中断不等于所有请求都未屏蔽。
- 类型号、向量地址和服务入口必须分清。
- 响应优先级与处理优先级可以不同。
- 屏蔽表先声明编码含义，执行轨迹记剩余时间。
- 程序中断正常数据传输仍通常由 CPU 执行。
- DMA 的 CPU 开销、总线时间、CPU 等待时间属于不同统计量。
- DMA 数据传送与完成中断可以出现在同一个任务中。
