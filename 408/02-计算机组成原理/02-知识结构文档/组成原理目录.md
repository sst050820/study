## 二、怎样逐章学习

### 2.1 第一轮：按 1—7 章建立完整过程

每次学习一个部分，按以下顺序：

1. 看地图，知道这部分接在哪个问题后面。
2. 读概念，能用自己的话说明它负责什么。
3. 跟着例题逐步计算，给每个数写上位宽、单位和含义。
4. 合上解析，独立重做同一个例题。
5. 用自测确认概念和适用条件。

如果读到某一步不能解释“为什么这样做”，回到该步的前提。例如算 Cache 组号前，先确定块大小、行数、路数和组数。

### 2.2 第二轮：按五条跨章线索串联

| 线索 | 串联顺序 | 重点辨析 |
|---|---|---|
| 位宽 | 数据类型 → 寄存器/ALU → 指令字段 → 数据总线 | 字长、指令长、地址长、总线宽度可以不同 |
| 地址 | 寻址得到虚拟地址 → TLB/页表 → 物理地址 → Cache/主存 | 虚拟页号、物理页号、块号、组号不是同一个编号 |
| 时序 | 时钟周期 → 指令周期 → 流水级 → 总线事务 → 中断/DMA | 首次延迟与连续吞吐要分开计算 |
| 性能 | IC/CPI/主频 → Cache 缺失 → 流水停顿 → I/O 开销 | 先确定统计边界，防止重复计入 |
| 程序 | C 语句 → 汇编 → 数据通路 → 访存 → I/O | 每步说明哪个部件在操作什么数据 |

地址线索是常见的教学模型；Cache 与地址转换的实际先后还要看虚拟/物理索引和标记方式，第三章已按不同条件说明。

### 2.3 第三轮：用同一段程序切换观察层次

以“读取数组元素并求和”为例：

- 第2章：元素类型如何解释，累加是否溢出。
- 第4章：数组下标如何变为地址，循环如何跳转。
- 第5章：LOAD 与 ADD 沿哪些阶段执行，是否发生相关停顿。
- 第3章：数组访问是否命中 Cache，是否跨块跨页。
- 第6章：缺失后取回一块数据需要哪些总线阶段。
- 第7章：数组若来自外设，由查询、中断还是 DMA 写入缓冲区。
- 第1章：所有这些因素最终怎样影响 CPU 时间和响应时间。

综合题不是额外的一套概念，而是同一过程包含了多个章节的观察角度。

## 三、公式使用前的检查

### 3.1 先固定计数单位

- 位数是 bit，容量和数据率可能是 B。
- KiB、MiB 按 $2^{10}$、$2^{20}$；KB、MB 在本笔记明确使用十进制的例题中按 $10^3$、$10^6$。
- 地址按字还是按字节编址，必须先明确。
- 一个事件是一个字、一个数据拍、一个中断还是一个 DMA 块，必须分清。

### 3.2 再固定统计范围

- CPU 时间是否包括等待、系统服务等题目指定部分。
- Cache 平均访问时间中的缺失代价是否已经包含探测时间。
- 流水线首尾填充、锁存开销和停顿是否都需要计入。
- 总线时间是否包含地址、仲裁、等待和数据。
- I/O 比例问 CPU 周期还是总线占用。

### 3.3 最后检查结果能否成立

结果位串可能存在，但原数学真值已经超出范围；平均带宽可能足够，但单次服务已经错过截止时间；处理优先级高的中断也必须满足开中断和未屏蔽等条件。

所有公式都要连同适用前提使用。
