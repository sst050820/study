# 第2章 线性表

> [!important] 本章必背 5 条（30 秒版）
> 1. 顺序表：随机访问 O(1)，插入删除 O(n)；链表：访问 O(n)，已知位置插删 O(1)。
> 2. 插入要右移且**从后往前**移；删除要左移且**从前往后**移，写反会覆盖数据。
> 3. 逻辑位序从 1 开始，数组下标从 0 开始，i 号位对应 data[i-1]。
> 4. 动态扩容 = 新申请 + 复制 + 释放，是 O(n)；不能因此把插入写成 O(1)。
> 5. 扩容后旧地址失效，原先指向旧数组内部的指针全部作废。
>

## 第一部分：线性表的定义与基本操作

对应视频：007；对应教材：2.1。

### 1.1 线性表描述什么关系

线性表是由有限个相同数据类型的元素组成的有序序列，可写成：

$$
L=(a_1,a_2,\ldots,a_n),\qquad n\ge 0
$$

这里的“有序”表示元素有确定的先后位置。例如：

```text
L = (8, 3, 8, 5)
     第1 第2 第3 第4个元素
```

它仍然是线性表，既不要求数值递增，也不要求各元素的值互不相同。两个值为 8 的元素占据不同位置。

线性表的关系是“一对一”：

- 当 $n>1$ 时，首元素没有直接前驱，尾元素没有直接后继。
- 除首元素外，每个元素恰有一个直接前驱。
- 除尾元素外，每个元素恰有一个直接后继。
- 当 $n=1$ 时，唯一元素既是首元素也是尾元素，没有直接前驱和直接后继。
- 当 $n=0$ 时，称为空表，没有任何数据元素。

在 `(8,3,8,5)` 中，第 2 个元素的直接前驱是第 1 个元素，直接后继是第 3 个元素。“直接”只指紧挨着的位置。

### 1.2 数据元素可以包含多个数据项

若每个元素都是一条学生记录：

```text
姓名 + 学号 + 分数
```

一条记录整体是一个数据元素，姓名、学号、分数是记录中的数据项。线性表要求各元素类型一致，不要求一个元素内部只能放一个整数。

长度 $n$ 统计的是元素个数，不是字段个数，也不是占用字节数。

### 1.3 线性表、顺序表和链表的关系

线性表先规定逻辑关系：“谁在谁前面，谁在谁后面”。顺序表和链表再规定如何存储这种关系。

```text
同一逻辑序列：(10, 20, 30)

顺序表：把10、20、30连续存放，位置本身反映顺序。
单链表：结点可以分散存放，用next保存后继地址。
```

因此，**线性表是逻辑结构；顺序表与链表是其常见存储表示。**使用链表不会把元素的逻辑关系改成“一对多”。

### 1.4 位序与下标必须分开

```text
元素：      10  20  30  40
逻辑位序：   1   2   3   4
数组下标：   0   1   2   3
```

第 $i$ 个元素对应 `data[i-1]`。反过来，`data[j]` 是第 $j+1$ 个元素。

例如“删除第 3 个元素”删除的是 30；写成 `data[3]` 就访问了 40。

### 1.5 基本操作到底在做什么

| 操作 | 含义 | 需要明确的条件 |
|---|---|---|
| 初始化 `InitList` | 建立一个空表 | 完成后得到合法空表；不覆盖尚未释放的旧结构 |
| 求长 `Length` | 返回有效元素个数 | 头结点不计入长度 |
| 按位查找 `GetElem` | 获取第 $i$ 个元素 | $1\le i\le n$ |
| 按值查找 `LocateElem` | 找与给定值相等的元素 | 重复值时需说明返回哪个 |
| 插入 `ListInsert` | 让新元素成为第 $i$ 个元素 | $1\le i\le n+1$ |
| 删除 `ListDelete` | 删除原来的第 $i$ 个元素 | $1\le i\le n$ |
| 判空 `Empty` | 判断是否没有有效元素 | 看对应存储表示的空表条件 |
| 销毁 `DestroyList` | 释放结构所占资源 | 动态内存需要逐一或整体释放 |

**插入为何有 $n+1$ 个合法位置？**长度为 3 的表有四个插入位置：

```text
□ 10 □ 20 □ 30 □
1    2    3    4
```

位置 4 表示表尾追加。删除只能删除已有元素，因此只有位置 1、2、3 合法。

清空与销毁也不同。清空后仍可保留表的容器或头结点；销毁通常连动态存储本身一起释放。

### 1.6 小例题：操作如何改变位序

初始 `L=(10,20,30)`，先在第 2 位插入 15，再删除第 3 个元素。

1. 插入前，第 2 个元素是 20；“在第 2 位插入”指把 15 放在 20 前面。
2. 插入后 `L=(10,15,20,30)`。
3. 删除针对当前表，第 3 个元素已变成 20。
4. 最终 `L=(10,15,30)`。

连续操作题中，每完成一步都要更新当前序列和长度，不能一直按初始位序理解。

## 第二部分：顺序表的定义与存储

对应视频：008；对应教材：2.2.1。

### 2.1 顺序存储为什么能随机存取

顺序表使用一组连续的存储单元，按逻辑次序存放元素。

假设首元素地址为 1000，每个元素占 4 字节：

```text
元素：  a1    a2    a3    a4
地址： 1000  1004  1008  1012
```

第 $i$ 个元素之前有 $i-1$ 个元素，所以：

$$
\boxed{LOC(a_i)=LOC(a_1)+(i-1)\times sizeof(ElemType)}
$$

例如第 4 个元素的地址为 $1000+3\times4=1012$。不需要先依次访问前 3 个元素，直接计算地址即可，这就是随机存取，按位访问时间为 $O(1)$。

“随机”指可以直接访问任意指定位置，不表示随机抽取元素。

### 2.2 表长与容量不是同一个量

设容量为 6，当前存了 3 个元素：

```text
data： [10, 20, 30, ?, ?, ?]
下标：   0   1   2  3  4  5
length = 3
capacity = 6
```

只有 `data[0]` 至 `data[2]` 属于有效区间。后面三个位置已分配空间，但不是表中元素，也不能把它们的旧值算入表长。

应始终满足：

$$
0\le length\le capacity
$$

删除一个元素后，通常只需更新有效区间和长度，不必把最后一个数组单元清零。

### 2.3 静态分配的顺序表

```cpp
#include <cstdlib>
#include <algorithm>
#include <vector>
using ElemType = int;
constexpr int MaxSize = 50;

struct SqList {
    ElemType data[MaxSize];
    int length;
};

void InitSqList(SqList &L) {
    L.length = 0;
}
```

`data` 是结构体内部的固定大小数组。初始化把长度设为 0，表示“目前没有有效元素”，不要求逐个把数组单元置零。

这里“静态分配”指容量在这种定义中固定，不能直接在原数组上增加。它不等同于 C++ 的 `static` 关键字或静态存储期。

### 2.4 动态分配仍然要求连续存储

```cpp
struct SeqList {
    ElemType *data;
    int capacity;
    int length;
};

bool InitSeqList(SeqList &L, int capacity) {
    L.data = nullptr;
    L.length = 0;
    L.capacity = 0;
    if (capacity <= 0) return false;

    L.data = static_cast<ElemType *>(
        std::malloc(sizeof(ElemType) * capacity));
    if (L.data == nullptr) return false;
    L.capacity = capacity;
    return true;
}
```

`data` 保存动态数组的首地址。动态分配可以在运行时决定容量、申请更大的数组，但有效元素仍按次序连续存放，因此仍是顺序表。

初始化函数用于首次建立表。若 `L` 已经拥有动态数组，应先释放旧数组，不能直接重新初始化而丢失原地址。

动态分配和链式存储是两个不同维度：前者讨论何时申请存储；后者讨论用什么方式表示元素之间的关系。

### 2.5 扩容为什么可能需要复制

假设原数组容量为 3，想扩到 6。原数组后方不一定还有连续空闲空间，稳妥的做法是：

1. 申请一个容量为 6 的新数组。
2. 把原来的 `length` 个有效元素复制过去。
3. 释放旧数组。
4. 更新首地址和容量，长度保持不变。

```cpp
bool IncreaseCapacity(SeqList &L, int delta) {
    if (delta <= 0) return false;
    // 假定容量计算和分配字节数在类型可表示范围内。
    int newCapacity = L.capacity + delta;
    ElemType *q = static_cast<ElemType *>(
        std::malloc(sizeof(ElemType) * newCapacity));
    if (q == nullptr) return false;

    for (int i = 0; i < L.length; ++i)
        q[i] = L.data[i];
    std::free(L.data);
    L.data = q;
    L.capacity = newCapacity;
    return true;
}
```

复制 $n$ 个元素花费 $O(n)$ 时间。不能因为“动态数组可以扩容”，就把一次需要扩容的插入写成严格的 $O(1)$。

扩容后旧数组地址可能失效，原先指向旧数组内部的指针也不能继续使用。这里的例程面向整数元素；含复杂资源的对象需使用对应的对象构造与销毁方式。

动态顺序表清空时可只令 `length=0`；销毁时还要归还数组：

```cpp
void DestroySeqList(SeqList &L) {
    std::free(L.data);
    L.data = nullptr;
    L.length = 0;
    L.capacity = 0;
}
```

此函数要求 L 已经初始化。固定数组不能传给 `free`，其存储随所属对象的生命周期管理。

### 2.6 本部分自检

- 顺序表连续存储，逻辑次序与物理存放次序一致。
- 动态分配的顺序表依然是顺序存储。
- 按位访问快，是因为可以直接计算地址。
- 当前表长不等于分配容量。

## 第三部分：顺序表的插入与删除

对应视频：009；对应教材：2.2.2。

### 3.1 插入操作先确定三件事

设当前长度为 $n$，要在第 $i$ 位插入 $x$：

1. 位置必须满足 $1\le i\le n+1$。
2. 固定容量表必须还有空位，即 `length < MaxSize`。
3. 原来第 $i$ 个及之后的元素都要右移一位。

例如：

```text
原表： [10, 20, 30, 40, ?]
在第2位插入15
结果： [10, 15, 20, 30, 40]
```

### 3.2 为什么必须从后向前移动

正确过程是：

```text
① data[4] = data[3]：先搬40
② data[3] = data[2]：再搬30
③ data[2] = data[1]：再搬20
④ data[1] = 15
```

如果先执行 `data[2]=data[1]`，原来的 30 会被 20 覆盖；随后再读 `data[2]`，就再也读不到原来的 30。

**右移从后向前，目的是先保护尚未搬走的数据。**

```cpp
bool ListInsert(SqList &L, int i, ElemType x) {
    if (i < 1 || i > L.length + 1) return false;
    if (L.length >= MaxSize) return false;

    for (int j = L.length; j >= i; --j)
        L.data[j] = L.data[j - 1];
    L.data[i - 1] = x;
    ++L.length;
    return true;
}
```

循环里 `j` 是目标数组下标。原尾元素在 `data[n-1]`，要写到 `data[n]`，所以第一次令 `j=n`；原第 $i$ 个元素在 `data[i-1]`，最后把它写到 `data[i]`，所以循环到 `j=i`。

空表在第 1 位插入时，`length=0`，移动循环一次也不执行，直接写 `data[0]`，随后长度变为 1。

### 3.3 插入的精确移动次数

需要移动原来的第 $i$ 个到第 $n$ 个元素：

$$
\boxed{M_{insert}=n-i+1}
$$

| 情况 | 插入位序 | 移动次数 | 时间 |
|---|---:|---:|---:|
| 表头插入 | $i=1$ | $n$ | $\Theta(n)$ |
| 表尾追加 | $i=n+1$ | $0$ | $\Theta(1)$，前提是容量足够 |
| 固定第 $i$ 位 | $i$ | $n-i+1$ | 取决于插入位置 |

若 $n+1$ 个合法位置等概率，移动次数为 $n,n-1,\ldots,0$，平均：

$$
E[M_{insert}]=\frac{n+(n-1)+\cdots+0}{n+1}=\frac n2
$$

所以通常所说顺序表插入平均时间为 $O(n)$。这里的“移动次数”不计把新元素写入空位的那一次赋值。

### 3.4 删除为什么从前向后覆盖

删除 `[10,20,30,40]` 的第 2 个元素：

```text
① 保存20，供调用者获取被删值
② data[1] = data[2]：30左移
③ data[2] = data[3]：40左移
④ length从4变成3

数组可能是 [10,30,40,40]
有效表是   [10,30,40]
```

若从后向前左移，先把 40 写入 `data[2]`，就会覆盖还没有搬走的 30。

```cpp
bool ListDelete(SqList &L, int i, ElemType &e) {
    if (i < 1 || i > L.length) return false;
    e = L.data[i - 1];
    for (int j = i; j < L.length; ++j)
        L.data[j - 1] = L.data[j];
    --L.length;
    return true;
}
```

`e` 是输出参数，返回被删除元素的值。循环从 `j=i` 开始，因为要把原第 $i+1$ 个元素 `data[i]` 搬到 `data[i-1]`。

### 3.5 删除的移动次数与复杂度

$$
\boxed{M_{delete}=n-i}
$$

删首元素移动 $n-1$ 个，删尾元素不移动。若 $n$ 个已有位置等概率：

$$
E[M_{delete}]=\frac{(n-1)+(n-2)+\cdots+0}{n}=\frac{n-1}{2}
$$

平均时间为 $O(n)$，最好时间为 $O(1)$。

### 3.6 小例题：先插再删的移动次数

原长度为 5，在第 3 位插入一个元素，再删除新表中的第 4 个元素。

1. 插入前 $n=5$，移动 $5-3+1=3$ 个元素。
2. 插入后长度变为 6。
3. 删除时移动 $6-4=2$ 个元素。
4. 两次合计移动 5 个元素。

第二步操作使用的是新的表长。若把删除的 $n$ 仍写成 5，就少算了一次移动。

## 第四部分：顺序表的按位查找与按值查找

对应视频：010；对应教材：2.2.2。

### 4.1 按位查找已经给出了位置

```cpp
bool GetSqElem(const SqList &L, int i, ElemType &e) {
    if (i < 1 || i > L.length) return false;
    e = L.data[i - 1];
    return true;
}
```

题目给“第 4 个元素”，只需读 `data[3]`，时间为 $O(1)$。检查位序后再访问数组，避免空表或非法位置越界。

### 4.2 按值查找只给出了目标值

在 `[10,40,20,30]` 中找 20，起初不知道它在哪个位置。一般从头逐个比较：

```text
10 ≠ 20 → 继续
40 ≠ 20 → 继续
20 = 20 → 找到，返回位序3
```

```cpp
int LocateSqElem(const SqList &L, ElemType x) {
    for (int j = 0; j < L.length; ++j)
        if (L.data[j] == x) return j + 1;
    return 0;
}
```

数组下标为 `j`，函数返回逻辑位序 `j+1`。返回 0 表示失败，因为有效位序从 1 开始。若表内有重复值，这段代码返回第一个匹配元素的位置。

若元素是学生等结构体，必须先定义“相等”指哪些字段相等。例如按学号查找就比较学号，按整条记录比较则检查规定的所有字段。普通 C 结构体不能直接用 `==` 比较；C++ 结构体也需要相应的比较运算定义，不能默认把整数版的判断原样套入。

### 4.3 比较次数如何算

成功找到第 $i$ 个元素需要比较 $i$ 次。成功查找各元素等概率时：

$$
E[C_{success}]=\frac{1+2+\cdots+n}{n}=\frac{n+1}{2}
$$

最坏情况找到最后一个元素，需要 $n$ 次；查找失败也需要把 $n$ 个元素全部比较完。通常按值顺序查找时间为 $O(n)$，成功的最好情况为 $O(1)$。

“顺序表支持随机存取”不能推出“按值查找是 $O(1)$”。随机存取解决的是已知位置如何访问，按值查找解决的是如何确定位置。

### 4.4 有序顺序表可以进一步利用大小关系

若表按非降序排列 `[10,20,30,40,50]`：

- 顺序查找 25 时，遇到 30 已大于 25，可以判定后面不会出现 25。
- 折半查找可利用大小关系，每次排除约一半候选区间，时间为 $O(\log n)$。

但“有序”不能使一般单链表获得与数组相同的随机存取能力。链表定位中间结点仍需沿链接访问。

折半查找的判定树、成功与失败平均查找长度在 [[第7章-查找-视频讲解整理|第7章 查找]] 中展开，本章先掌握它对有序顺序存储的要求。

### 4.5 本部分自检

| 问法 | 是否已知位置 | 一般顺序表时间 |
|---|---|---:|
| 获取第 $i$ 个元素 | 已知 | $O(1)$ |
| 查找值为 $x$ 的元素 | 未知 | $O(n)$ |
| 在有序顺序表中折半查找 $x$ | 未知，但可排除半区 | $O(\log n)$ |

## 第五部分：单链表的定义与指针基础

对应视频：011；对应教材：2.3.1。

### 5.1 链表如何把分散的结点串起来

顺序表依靠连续位置表示前后关系；单链表把“后继在哪里”单独存入结点。

```cpp
struct LNode {
    ElemType data;
    LNode *next;
};
using LinkList = LNode *;
```

`data` 保存元素值，`next` 保存后继结点地址。例如：

```text
地址100处：[10 | 500]
地址500处：[20 | 300]
地址300处：[30 | nullptr]

逻辑顺序：10 → 20 → 30
```

后继结点不必位于更大的地址。访问次序由 `next` 决定，不能把结点地址排序当成链表次序。

每个结点内部仍需存放自己的字段；链式存储的“不连续”指不同结点之间不要求连续。

### 5.2 指针变量、结点与数据域

设 `p` 指向值为 20 的结点：

| 表达式 | 含义 |
|---|---|
| `p` | 该结点的地址 |
| `*p` | 地址处的整个结点 |
| `p->data` | 结点中的数据值 20 |
| `p->next` | 后继结点的地址 |
| `p = p->next` | 把变量 `p` 改为指向后继 |
| `p->next = q` | 改变结点内部的链接，使其后继变为 `q` |

最后两条尤其容易混淆：

- `p=p->next` 只是移动观察位置，没有修改链表。
- `p->next=q` 修改了链表结构，原来的后继可能因此失去访问路径。

读取 `p->data` 或 `p->next` 之前必须保证 `p` 指向有效结点。`p==nullptr` 时不能解引用。

### 5.3 头指针、头结点与首元结点

带头结点的单链表：

```text
头指针L
   ↓
[头结点] → [10] → [20] → [30] → nullptr
             ↑
          首元结点
```

**头指针**是指向链表起始结点的指针变量；**头结点**是额外设置的结点；**首元结点**是第一个实际保存表元素的结点。

头结点通常不保存有效元素，或用于保存附加信息。不论如何，本章把它排除在数据元素位序和表长之外。

不带头结点时：

```text
L → [10] → [20] → [30] → nullptr
     首元结点
```

此时头指针直接指向首元结点。每条链表都需要某种起始引用来访问，但不一定设置头结点。

### 5.4 两种空表条件为什么不同

| 表示 | 空表状态 | 已初始化空表的含义 |
|---|---|---|
| 带头结点 | `L != nullptr` 且 `L->next == nullptr` | 容器头结点存在，没有数据结点 |
| 不带头结点 | `L == nullptr` | 连首元结点也没有 |

带头结点链表若 `L==nullptr`，表示没有有效头结点，例如尚未成功初始化或已经销毁。不能直接访问 `L->next`。

```cpp
bool InitLinkList(LinkList &L) {
    L = static_cast<LNode *>(std::malloc(sizeof(LNode)));
    if (L == nullptr) return false;
    L->next = nullptr;
    return true;
}
```

这段函数创建的是头结点，把 `next` 设为空后，得到长度为 0 的表。头结点的 `data` 不作为表元素读取。

它同样用于首次创建；已有旧表时先销毁旧表，再创建新表。

### 5.5 为什么引用参数有时必需、有时不必

普通指针参数传入的是地址的副本：

```cpp
void MovePointer(LinkList p) {
    p = p->next;   // 只改变局部指针p
}
```

调用者的头指针不会随 `p` 的移动而改变。但局部指针与调用者指向同一个结点，所以 `p->next=...` 对结点的修改仍然可见。

初始化中要把新申请的地址交给调用者，因此使用 `LinkList &L`。不带头结点链表的表头插入或删除也可能改变头指针，同样需要引用参数，或者用 C 的二级指针、返回新头指针等方式实现。

带头结点链表在首元前插入时，只需改 `L->next`，头指针本身不变。不能把“需要修改链接”一概理解为“指针参数必须带引用”。

### 5.6 清空与销毁的具体实现

```cpp
void ClearLinkList(LinkList L) {
    if (L == nullptr) return;
    LNode *p = L->next;
    while (p != nullptr) {
        LNode *q = p->next;
        std::free(p);
        p = q;
    }
    L->next = nullptr;
}

void DestroyLinkList(LinkList &L) {
    if (L == nullptr) return;
    ClearLinkList(L);
    std::free(L);
    L = nullptr;
}
```

释放当前结点前先保存后继地址。若先释放 `p`，再读 `p->next`，就会访问已经失效的内存。

清空保留头结点，销毁再释放头结点并把调用者的头指针设为空。两者处理 $n$ 个数据结点均需 $O(n)$ 时间，辅助空间为 $O(1)$。

## 第六部分：单链表的插入与删除

对应视频：012；对应教材：2.3.2。

### 6.1 后插的核心是保住原后继

在结点 `p` 后插入新结点 `s`：

```text
原来：p → q
目标：p → s → q
```

正确语句：

```cpp
s->next = p->next;
p->next = s;
```

逐步理解：

1. `s->next=p->next`，先把原后继 `q` 的地址保存在新结点中。
2. `p->next=s`，再让前驱指向新结点。

若反过来：

```cpp
p->next = s;
s->next = p->next;
```

第二句读到的 `p->next` 已经是 `s`，于是 `s->next=s`，新结点形成自环，原后续链也失去原来的入口。

```cpp
bool InsertAfter(LNode *p, ElemType x) {
    if (p == nullptr) return false;
    LNode *s = static_cast<LNode *>(std::malloc(sizeof(LNode)));
    if (s == nullptr) return false;
    s->data = x;
    s->next = p->next;
    p->next = s;
    return true;
}
```

给定有效 `p` 后，后插只需常数次指针操作，按本章模型计为 $O(1)$。尾结点的 `p->next` 为空也没有问题，新结点成为新尾结点。

### 6.2 按位插入为何要找第 $i-1$ 个结点

让新元素成为第 $i$ 个元素，等价于在原第 $i-1$ 个结点后插入。

带头结点时把头结点当作辅助的“第 0 个结点”：

```text
辅助位序： 0       1      2      3
          头 →    10 →   20 →   30

在第1位插入：在头结点后插。
在第3位插入：在原第2个数据结点20后插。
在第4位插入：在原尾结点30后插。
```

```cpp
bool LinkInsert(LinkList L, int i, ElemType x) {
    if (L == nullptr || i < 1) return false;
    LNode *p = L;
    int j = 0;
    while (p != nullptr && j < i - 1) {
        p = p->next;
        ++j;
    }
    if (p == nullptr) return false;
    return InsertAfter(p, x);
}
```

当 $i>n+1$ 时，找不到所需前驱，返回失败。空表在第 1 位插入时，直接使用头结点作前驱，不必写特殊的表头分支。

### 6.3 链表插入的 $O(1)$ 前提是什么

按位插入包含两段工作：

$$
T=T_{定位前驱}+T_{局部后插}
$$

后插是 $O(1)$，但从表头走到指定前驱最坏为 $O(n)$。所以普通单链表按位插入通常为 $O(n)$。

题目若直接给出前驱指针 `p`，才可以直接采用 $O(1)$ 的局部插入。题目只给“第 $i$ 个位置”时，不能把定位成本省略。

### 6.4 删除后继：先保存，后断链，再释放

已知前驱 `p`，删除其后继 `q`：

```text
原来：p → q → r
目标：p ───→ r
```

```cpp
bool DeleteAfter(LNode *p, ElemType &e) {
    if (p == nullptr || p->next == nullptr) return false;
    LNode *q = p->next;
    e = q->data;
    p->next = q->next;
    std::free(q);
    return true;
}
```

1. 保存 `q`，否则改链后可能找不到要释放的结点。
2. 保存被删值 `e`，因为释放后不能再读取。
3. 把前驱接到 `q` 的后继，保持余下链表可达。
4. 释放 `q`。

`std::free(q)` 只是归还内存，不会自动修补链表链接。必须先保证其他结点不再通过本条链接访问它。

### 6.5 按位删除与按位插入的边界区别

```cpp
bool LinkDelete(LinkList L, int i, ElemType &e) {
    if (L == nullptr || i < 1) return false;
    LNode *p = L;
    int j = 0;
    while (p != nullptr && j < i - 1) {
        p = p->next;
        ++j;
    }
    return DeleteAfter(p, e);
}
```

插入只需前驱存在；删除还需要前驱的后继存在。例如长度为 3 时，第 4 位插入合法，但删除第 4 个元素不合法。

按位删除最坏时间为 $O(n)$；若前驱已经给出，局部删除为 $O(1)$。

### 6.6 给定结点前插：两种处理

若给定 `p`，要在它之前插入 $x$：

**方法一：查找前驱。**从头结点出发，找满足 `pre->next==p` 的结点，在 `pre` 后插入。最坏 $O(n)$，真正的新结点位于 `p` 前面。

**方法二：后插并交换数据。**如果题目只要求元素值的逻辑序列正确，可以在 `p` 后新建结点，把原来 `p` 的数据移入新结点，再把 $x$ 写入 `p`。

```text
原来：   [20]p → [30]
后插：   [20]p → [新]s → [30]
改数据： [15]p → [20]s → [30]
```

```cpp
bool InsertBeforeByData(LNode *p, ElemType x) {
    if (p == nullptr) return false;
    LNode *s = static_cast<LNode *>(std::malloc(sizeof(LNode)));
    if (s == nullptr) return false;
    s->data = p->data;
    s->next = p->next;
    p->next = s;
    p->data = x;
    return true;
}
```

时间为 $O(1)$，但原来地址 `p` 处的结点内容发生变化。如果题目要求保持结点身份，或外部指针必须继续指向原来的那个数据元素，就不能随意采用这种技巧。

### 6.7 只给当前结点指针，如何“删除”

若 `p` 有后继 `q`，可以把 `q` 的数据复制到 `p`，再删除 `q`：

```cpp
bool DeleteByCopy(LNode *p) {
    if (p == nullptr || p->next == nullptr) return false;
    LNode *q = p->next;
    p->data = q->data;
    p->next = q->next;
    std::free(q);
    return true;
}
```

它让原 `p` 所保存的元素值从序列中消失，但真正释放的是后继结点。因此也有结点身份方面的限制。

**尾结点没有后继，不能使用这种技巧。**只给普通单链表尾结点指针，又没有前驱时，要真正删除尾结点通常需从头寻找前驱，时间为 $O(n)$。

### 6.8 不带头结点时：第 1 位要单独处理

不带头结点链表的 `L` 直接指向首元。第 1 位插入没有可用的前驱结点，需要让新结点成为新头；第 1 位删除则需要让原首元的后继成为新头。

```cpp
bool InsertNoHead(LinkList &L, int i, ElemType x) {
    if (i < 1) return false;
    if (i == 1) {
        LNode *s = static_cast<LNode *>(std::malloc(sizeof(LNode)));
        if (s == nullptr) return false;
        s->data = x;
        s->next = L;
        L = s;
        return true;
    }
    LNode *p = L;
    int j = 1;
    while (p != nullptr && j < i - 1) {
        p = p->next;
        ++j;
    }
    return InsertAfter(p, x);
}

bool DeleteNoHead(LinkList &L, int i, ElemType &e) {
    if (i < 1 || L == nullptr) return false;
    if (i == 1) {
        LNode *q = L;
        e = q->data;
        L = q->next;
        std::free(q);
        return true;
    }
    LNode *p = L;
    int j = 1;
    while (p != nullptr && j < i - 1) {
        p = p->next;
        ++j;
    }
    return DeleteAfter(p, e);
}
```

与带头结点版本比较：起始计数变成 `j=1`，首元插删改变 L，所以参数需要引用。普通位置仍是寻找第 $i-1$ 个结点，再执行后插或删除后继。

头结点的价值就在于把“第 1 位”也转换成一个有前驱的普通位置，减少分支。

### 6.9 指针题的局部检查方法

写代码前先画“前驱—目标—后继”。写完检查：

1. 余下链表是否仍可从头结点访问到。
2. 有无结点指向自己，或意外形成环。
3. 被删除结点是否已释放，后续是否还访问了它。
4. 空表、首元、尾元和单个数据结点能否处理。

## 第七部分：单链表的查找与求长

对应视频：013；对应教材：2.3.2。

### 7.1 按位查找为什么需要顺序走

单链表第 $i$ 个结点的地址不能由首地址加偏移量得到。要找到它，必须沿 `next` 链移动。

```cpp
LNode *GetLinkElem(LinkList L, int i) {
    if (L == nullptr || i < 0) return nullptr;
    LNode *p = L;
    int j = 0;
    while (p != nullptr && j < i) {
        p = p->next;
        ++j;
    }
    return p;
}
```

这段辅助函数允许 `i=0` 返回头结点，便于查找插删操作的前驱。真正获取第 $i$ 个数据元素时，仍要求 $i\ge1$。

例如查找第 3 个数据结点：

```text
j=0：p指向头结点
j=1：p指向第1个数据结点
j=2：p指向第2个数据结点
j=3：p指向第3个数据结点，返回
```

若不足 $i$ 个结点，最终 `p==nullptr`，表示查找失败。访问第 $i$ 个数据结点需从头移动 $i$ 次链接，最坏为 $O(n)$。

### 7.2 按值查找从首元开始

```cpp
LNode *LocateLinkElem(LinkList L, ElemType x) {
    if (L == nullptr) return nullptr;
    LNode *p = L->next;
    while (p != nullptr && p->data != x)
        p = p->next;
    return p;
}
```

头结点没有有效数据，应跳过。代码先检查 `p!=nullptr`，再读取 `p->data`；利用 `&&` 的短路求值避免空指针访问。

找到后返回结点地址，失败返回空指针；与顺序表按值查找常返回位序的接口不同。分析题目时必须先看返回值约定。

### 7.3 求长为什么通常是 $O(n)$

```cpp
int LinkLength(LinkList L) {
    if (L == nullptr) return 0;
    int n = 0;
    for (LNode *p = L->next; p != nullptr; p = p->next)
        ++n;
    return n;
}
```

普通表示没有维护长度字段，必须数完所有数据结点，时间为 $O(n)$，头结点不计入。

顺序表常直接维护 `length`，求长为 $O(1)$。若链表也额外维护长度，并在每次插删时更新，那么它的求长也可以是 $O(1)$。复杂度取决于表示中保存了什么信息。

### 7.4 小例题：相同的“查找”为什么成本不同

长度为 100 的表，题目分别要求获取第 90 个元素与查找值 90。

- 顺序表获取第 90 个元素：访问 `data[89]`，$O(1)$。
- 单链表获取第 90 个元素：沿链接定位，$O(n)$。
- 两种表一般按值查找 90：逐个比较，均为 $O(n)$。

不能因为元素值恰好等于位序，就把“值为 90”擅自改成“第 90 个元素”。

## 第八部分：单链表的建立——头插法与尾插法

对应视频：014；对应教材：2.3.2。

### 8.1 头插法让每个新结点成为首元

输入顺序为 `1,2,3`：

```text
开始：L → nullptr
读1： L → 1 → nullptr
读2： L → 2 → 1 → nullptr
读3： L → 3 → 2 → 1 → nullptr
```

每次都在头结点后插入，所以后读入的元素排在先读入的元素前面，最终得到输入逆序。

```cpp
bool BuildHead(LinkList &L, const ElemType a[], int n) {
    if (n < 0 || !InitLinkList(L)) return false;
    for (int i = 0; i < n; ++i) {
        if (!InsertAfter(L, a[i])) {
            DestroyLinkList(L);
            return false;
        }
    }
    return true;
}
```

这里按已知长度的数组建表，`L` 作为输出变量使用，调用前不应让它占有尚未释放的旧表。每个结点后插为 $O(1)$，共 $n$ 个结点，建表时间为 $O(n)$。

视频、教材常用 `9999` 等值作为输入终止标志。那是输入约定，使用这种方式时该值不能同时作为普通有效输入。建表思想不依赖特定终止值。

### 8.2 头结点的 `next` 为什么必须先置空

最开始执行 `s->next=L->next`。若 `L->next` 没有正确初始化，新结点就会连到不确定的地址。

所以应先建立：

```text
L → nullptr
```

再逐个插入。初始化是保证后续插入合法的前提。

### 8.3 尾插法如何保持输入顺序

尾插法维护尾指针 `r`，每次把新结点接在当前尾结点之后：

```text
开始：L → nullptr，r=L
读1： L → 1 → nullptr，r指向1
读2： L → 1 → 2 → nullptr，r指向2
读3： L → 1 → 2 → 3 → nullptr，r指向3
```

```cpp
bool BuildTail(LinkList &L, const ElemType a[], int n) {
    if (n < 0 || !InitLinkList(L)) return false;
    LNode *r = L;
    for (int i = 0; i < n; ++i) {
        LNode *s = static_cast<LNode *>(std::malloc(sizeof(LNode)));
        if (s == nullptr) {
            DestroyLinkList(L);
            return false;
        }
        s->data = a[i];
        s->next = nullptr;
        r->next = s;
        r = s;
    }
    return true;
}
```

`r->next=s` 把新结点接上；`r=s` 更新尾指针。若忘记更新 `r`，后续插入仍在旧尾后操作，可能覆盖之前建立的链接。

空表时 `r=L`，头结点也承担初始尾位置，第一步插入不需要特殊处理。

### 8.4 不维护尾指针为什么会退化

假设每读入一个元素都重新从表头寻找尾结点。建立 $n$ 个结点时，找尾的访问次数约为：

$$
0+1+2+\cdots+(n-1)=\frac{n(n-1)}2
$$

因此总时间变成 $O(n^2)$。维护尾指针可以避免重复定位，把总时间降到 $O(n)$。

### 8.5 建表与辅助空间的口径

两种建表方式都要创建 $n$ 个数据结点，结果链表占用 $O(n)$ 存储。算法除了结果本身，只使用几个指针变量，因此**辅助空间为 $O(1)$**。

若题目问“新申请的存储总量”，应回答 $O(n)$；若问“除结果链表外的额外工作空间”，通常回答 $O(1)$。

### 8.6 小例题：建立非降序链表

输入依次为 `2,4,6,8`：

- 尾插得到 `2→4→6→8`，保留非降序。
- 头插得到 `8→6→4→2`，变为非升序。
- 输入若本来无序，头插只会反转输入次序，不会自动排序。

头插法还可以用于链表逆置：把已有结点逐个摘下，再插入头结点之后。这一应用在第十四部分展开。

## 第九部分：双链表——同时维护前驱与后继

对应视频：015；对应教材：2.3.3。

### 9.1 双链表增加了什么

单链表结点只能直接找到后继，双链表额外保存前驱地址：

```cpp
struct DNode {
    ElemType data;
    DNode *prior;
    DNode *next;
};
using DLinkList = DNode *;

bool InitDLinkList(DLinkList &L) {
    L = static_cast<DNode *>(std::malloc(sizeof(DNode)));
    if (L == nullptr) return false;
    L->prior = nullptr;
    L->next = nullptr;
    return true;
}
```

```text
头 ⇄ 10 ⇄ 20 ⇄ 30
          p
```

若 `p` 指向 20，则 `p->prior` 指向 10，`p->next` 指向 30。查找某个尚未定位的结点仍需遍历；增加前驱指针不会产生数组那样的随机存取能力。

对相邻结点 `p,q` 应保持：

```text
p->next == q
q->prior == p
```

插删时必须同时维护这两个方向，否则从前往后看可能正确，从后往前走却会断链或进入已释放结点。

### 9.2 在 `p` 后插入新结点

原结构 `p ⇄ q`，目标 `p ⇄ s ⇄ q`，共需建立四条关系：

```text
s的前驱 = p
s的后继 = q
p的后继 = s
q的前驱 = s
```

```cpp
bool DInsertAfter(DNode *p, ElemType x) {
    if (p == nullptr) return false;
    DNode *s = static_cast<DNode *>(std::malloc(sizeof(DNode)));
    if (s == nullptr) return false;
    DNode *q = p->next;

    s->prior = p;
    s->next = q;
    if (q != nullptr) q->prior = s;
    p->next = s;
    s->data = x;
    return true;
}
```

先把原后继保存到 `q`，再修改链接，使原后继不会因覆盖 `p->next` 而丢失。若不用临时变量保存，语句次序就更受限制。

这不是说四句只有一个合法执行顺序。关键是：读取原后继的地址之前，不能先覆盖保存它的唯一链接。

若 `p` 是普通非循环双链表的尾结点，`q==nullptr`，此时无需修改后继的 `prior`，其余操作照常。不能直接执行 `p->next->prior=s`。

### 9.3 删除一个已知数据结点

删除 `q` 时：

```text
原来：p ⇄ q ⇄ r
目标：p ⇄ r
```

```cpp
bool DDeleteNode(DNode *q, ElemType &e) {
    // 默认带头结点、非循环双链表，q必须是数据结点。
    if (q == nullptr || q->prior == nullptr) return false;
    DNode *p = q->prior;
    DNode *r = q->next;
    e = q->data;
    p->next = r;
    if (r != nullptr) r->prior = p;
    std::free(q);
    return true;
}
```

已知 `q` 后，前驱可直接通过 `prior` 得到，因此删除为 $O(1)$。普通单链表若只知道 `q`，则未必能直接获得前驱。

删首元时前驱是头结点，删尾元时后继为空。带头结点表示使首元删除不必改变头指针。

### 9.4 在 `p` 前插入新结点如何推导

令 `q=p->prior`。如果 `p` 是数据结点，则带头结点表示下 `q` 一定存在；在 `q` 后插入就是在 `p` 前插入。

考试若给的是具体四条指针语句，不必孤立背选项。先画：

```text
q ⇄ p   变为   q ⇄ s ⇄ p
```

再逐条检查新结点和左右邻居的前后链接是否都正确。

### 9.5 双链表的收益与成本

- 已知结点后，可以 $O(1)$ 访问直接前驱和后继。
- 已知数据结点，可以 $O(1)$ 局部删除，表头、表尾按约定处理。
- 每个结点多存一个指针，空间开销更大。
- 按位或按值查找一般仍为 $O(n)$。

不能只看到“多了一个指针”，就把双链表所有操作都写成 $O(1)$。

## 第十部分：循环单链表与循环双链表

对应视频：016；对应教材：2.3.4。

### 10.1 循环单链表改变了尾链接

普通单链表尾结点的 `next` 为空；带头结点的循环单链表尾结点的 `next` 指回头结点：

```text
L → 头 → 10 → 20 → 30
     ↑______________|
```

因此 `next==nullptr` 不再是正常的表尾标志。

```text
空表：L->next == L
尾结点p：p->next == L
```

只有一个数据结点时：`L->next=p`，`p->next=L`。数据结点不计头结点，表长为 1。

首次初始化只需把新头结点的后继设为自身：

```cpp
bool InitCircular(LinkList &L) {
    if (!InitLinkList(L)) return false;
    L->next = L;
    return true;
}
```

### 10.2 循环表遍历为何不能套普通单链表

```cpp
int CircularLength(LinkList L) {
    if (L == nullptr) return 0;
    int n = 0;
    for (LNode *p = L->next; p != L; p = p->next)
        ++n;
    return n;
}
```

从首元开始，重新遇到头结点时停止。空表起初 `p==L`，循环不执行。

如果写 `while(p!=nullptr)`，合法循环链表里始终遇不到空指针，程序会一直循环。此处假设结构已正确初始化为循环表，不能把损坏的链接当作合法输入。

### 10.3 只设尾指针时，头结点在哪里

带头结点循环单链表只保存尾指针 `R`：

```text
R → 尾结点
R->next → 头结点
非空时 R->next->next → 首元结点
```

空表里头结点也承担尾位置：

```text
R指向头结点，R->next == R
```

有头结点与无头结点不能混写：不带头结点的非空循环单链表中，`R->next` 就是首元；带头结点时它是头结点。

### 10.4 尾指针如何使表尾插入变成 $O(1)$

带头结点循环单链表在尾部追加：

```cpp
bool CircularAppend(LinkList &R, ElemType x) {
    // R指向尾结点；空表时R指向自环头结点。
    if (R == nullptr) return false;
    LNode *s = static_cast<LNode *>(std::malloc(sizeof(LNode)));
    if (s == nullptr) return false;
    s->data = x;
    s->next = R->next;
    R->next = s;
    R = s;
    return true;
}
```

先让新结点指回头结点，再让旧尾指向新结点，最后更新尾指针。头结点地址保持不变。

如果只保存头指针，通常要先遍历找到尾结点，追加仍是 $O(n)$；只保存尾指针则可以同时快速得到尾结点和头结点，在表头、表尾插入均可 $O(1)$。

**但只设尾指针，删除尾结点通常仍是 $O(n)$。**单链表仍然没有直接前驱指针，必须寻找尾结点前驱。

### 10.5 循环双链表的首尾关系

循环双链表既有 `next`，也有 `prior`，并把首尾接成环。带头结点时：

```text
L->next  → 首元结点
L->prior → 尾结点
首元->prior == L
尾元->next == L
```

空表两个方向都指向头结点自身：

$$
\boxed{L\texttt{->next}=L,\qquad L\texttt{->prior}=L}
$$

在头结点后插入时，即使原表为空，原“后继”也是真实存在的头结点，因此四条链接语句可以统一使用，不需普通双链表表尾的空后继分支。

初始化时要同时建立两个自环：

```cpp
bool InitCircularDouble(DLinkList &L) {
    if (!InitDLinkList(L)) return false;
    L->next = L;
    L->prior = L;
    return true;
}
```

### 10.6 在循环双链表中删除结点

前提：`q` 是有效数据结点且 `q!=L`。

```cpp
q->prior->next = q->next;
q->next->prior = q->prior;
std::free(q);
```

当表里只剩一个数据结点时，其前驱和后继都是 `L`。两次赋值后，`L->next=L`、`L->prior=L`，自然恢复空表。

如果误删头结点，其他结点的终止标记和起始引用都会被破坏。判断是否为空时也应比较链接是否回到头结点，不能检查 `L==nullptr`。

### 10.7 两个循环单链表的拼接：尾指针的另一用途

两表均带头结点，只保存尾指针。希望把 B 的数据链接到 A 后面：

```text
A：头A → 1 → 2 → 头A，尾指针R1指向2
B：头B → 3 → 4 → 头B，尾指针R2指向4
结果A：头A → 1 → 2 → 3 → 4 → 头A
结果B：头B自环，空表
```

因为 R1、R2 已给出，可以立即获得两个头结点和 B 的首元，只需改少数链接：

```cpp
// 两表正确初始化、结点互不共享；B的数据结点转交给A。
bool ConcatCircular(LinkList &R1, LinkList &R2) {
    if (R1 == nullptr || R2 == nullptr) return false;
    LNode *headA = R1->next;
    LNode *headB = R2->next;
    if (headA == headB) return false;
    if (R2 == headB) return true;  // B为空，A不需改变
    R1->next = headB->next;
    R2->next = headA;
    R1 = R2;                      // A的新尾是B的原尾
    headB->next = headB;
    R2 = headB;                   // B恢复带头结点的空表
    return true;
}
```

若 A 原本为空，R1 指向头A，第一句改链正好把 B 的首元接到头A后面，仍然适用。时间 $O(1)$，辅助空间 $O(1)$。

只保存头指针时，为了修改尾链接还要找到两个表尾，通常需 $O(m+n)$。所以“拼接循环链表为 $O(1)$”也有已给尾位置的前提。

### 10.8 本部分辨析

| 结构，均按带头结点表示 | 空表条件 | 正常尾结点的后继 |
|---|---|---|
| 普通单链表 | `L->next==nullptr` | `nullptr` |
| 循环单链表 | `L->next==L` | `L` |
| 普通双链表 | `L->next==nullptr` | `nullptr` |
| 循环双链表 | `L->next==L && L->prior==L` | `L` |

循环表可以从任一结点沿链接走到其余结点；是否能直接访问前驱，仍取决于是单链还是双链。

## 第十一部分：静态链表——用数组下标模拟指针

对应视频：017；对应教材：2.3.5。

### 11.1 数组中的位置与逻辑位序可以不同

静态链表预先分配数组，每个数组单元保存数据和后继游标：

```cpp
struct StaticNode {
    ElemType data;
    int next;
};
```

游标是数组下标，用来指示后继在哪个单元。数组单元在物理上连续，但有效元素的逻辑顺序由游标决定，所以静态链表采用的是链式组织方式。

例如约定下标 0 为头结点，`-1` 表示有效链结束：

| 下标 | data | next |
|---:|---:|---:|
| 0 | 头结点，无有效值 | 3 |
| 1 | 30 | -1 |
| 2 | 空闲 | 空闲标记 |
| 3 | 10 | 4 |
| 4 | 20 | 1 |

沿游标走：

```text
0 → 3 → 4 → 1 → -1
    10   20   30
```

逻辑第 1 个元素存于下标 3，逻辑第 2 个存于下标 4。不能用 `S[1]` 直接获取逻辑第 1 个元素。

### 11.2 已知前驱时怎样插入

若前驱在下标 `p`，已取得一个空闲单元 `s`：

```cpp
S[s].data = x;
S[s].next = S[p].next;
S[p].next = s;
```

与动态单链表的 `s->next=p->next; p->next=s;` 完全对应，只是把地址访问换成数组下标访问。

插入不必移动其余有效元素。即使 `s` 的数组下标大于所有原结点，也可以成为逻辑首元素。

### 11.3 删除与回收空闲位置

删除 `p` 的后继：

```cpp
int q = S[p].next;
S[p].next = S[q].next;
// 再把下标q归还空闲位置管理结构。
```

使用前必须保证 `q!=-1`，并且游标都在有效数组范围内。断开链接后，原数组单元还存在；它只是退出有效链，数据旧值可能仍在。

空闲单元可以通过额外标记判断，也可以串成备用链表。备用链表保存的是可复用的数组下标：申请时摘下一个下标，释放时把下标接回备用链。

若结点池容量为 $N$，用 `-2` 表示空闲、每次扫描整个数组找空闲槽，申请一次最坏为 $O(N)$；若维护备用链表并直接取其表头，可以 $O(1)$ 获得槽位。容量 N 与当前有效表长 n 不一定相等，具体标记与管理方式必须看题目约定。

### 11.4 静态链表的复杂度要分两段

- 已知前驱下标、已取得空闲槽：局部插入或删除为 $O(1)$。
- 按逻辑位序定位：仍需沿游标，最坏 $O(n)$。
- 若找空闲位置要扫描数组，还需计入扫描成本。

数组可以随机访问物理单元，不等于能随机访问静态链表的第 $i$ 个逻辑元素。

### 11.5 为什么称为“静态”

它的结点池通常是预先分配的固定大小数组，增加元素受结点池容量限制。“静态”不表示元素不能增删，而是强调这类存储管理方式与逐结点动态申请内存不同。

核心要记住：**数组是结点池，游标是链接，逻辑次序沿游标读取。**

## 第十二部分：顺序表与链表的比较和选型

对应视频：018；对应教材：2.3.6。

### 12.1 存储关系与访问方式

| 比较项 | 顺序表 | 链表 |
|---|---|---|
| 元素之间的关系 | 由连续存放位置体现 | 由指针或游标体现 |
| 存储要求 | 数组需要连续空间 | 动态结点之间不要求连续 |
| 附加存储 | 容量可能超过当前长度 | 结点有指针字段，通常还有头结点 |
| 按位访问 | 直接地址计算，$O(1)$ | 一般沿链接定位，$O(n)$ |
| 未排序时按值查找 | 一般 $O(n)$ | 一般 $O(n)$ |
| 长度变化 | 固定容量或扩容 | 动态链表可逐结点申请和释放 |

“链表一定更节省空间”不成立。链表有指针开销，顺序表有容量余量；实际占用取决于元素大小、指针大小、表长和预留容量。

### 12.2 插删比较必须明确“已知什么”

| 任务与条件 | 顺序表 | 普通单链表 | 普通双链表 |
|---|---:|---:|---:|
| 已知第 $i$ 位，插入一个元素 | 定位 $O(1)$，通常需移动，合计 $O(n)$ | 找前驱 $O(n)$，改链 $O(1)$ | 定位 $O(n)$，改链 $O(1)$ |
| 已知合适前驱，局部后插 | 数组通常需搬移 | $O(1)$ | $O(1)$ |
| 已知某数据结点，真正删除它 | 数组通常需搬移 | 一般仍需前驱；尾结点尤需注意 | 直接用 `prior`，$O(1)$ |
| 表尾追加 | 容量足够时 $O(1)$ | 有尾指针时 $O(1)$，否则 $O(n)$ | 有尾指针或循环头的 `prior` 时 $O(1)$ |

这里的表尾追加排除了需要扩容的顺序表情形。位置靠近尾部时，顺序表移动次数可能很少；复杂度表表示一般或最坏量级，不代表每一次操作都移动 $n$ 个元素。

### 12.3 “第 $i$ 个结点前插入”和“给定结点前插入”

前者先给的是位序，需要定位；后者已给地址。

- 顺序表：第 $i$ 个位置直接可得，主要成本是移动。
- 单链表：按位定位需要遍历；给定结点时，数据交换技巧可能把“值序列前插”做成 $O(1)$，但有身份限制。
- 双链表：给定结点后可直接获得前驱，真正的前插可 $O(1)$。

答题时要把题目条件写进分析中，尤其不能把特殊技巧推广到所有链表插删。

### 12.4 结构怎样选

**频繁按位访问、遍历、二分查找，长度较稳定：**优先考虑顺序表。连续存储也通常有较好的缓存局部性。

**数据长度变化大、已定位处频繁插删：**可考虑链表。减少大块移动，也能逐结点申请空间。

**频繁从某结点向前、向后移动：**可考虑双链表。需要接受额外指针开销。

**经常操作首尾，希望快速由尾访问头：**可考虑带尾指针的循环单链表；若还要 $O(1)$ 真正删除尾结点，循环双链表更方便。

**预先分配结点池、用整数下标管理结点：**可考虑静态链表，但容量与空闲位置管理成本仍需分析。

结构选型要看主导操作。单纯“链表插删快”不足以解释一个需要先按位定位、再插入的工作负载。

## 第十三部分：顺序表综合算法

这一部分对应教材 2.2 的综合习题。前四部分解决基本操作，这里把它们组合成完整算法。每题先确定：**是否有序、是否保留相对次序、是否允许额外数组、是否要求原地操作。**

### 13.1 稳定删除所有值为 $x$ 的元素：读写双指针

假设顺序表为：

```text
[2, 1, 2, 3, 2]，删除所有 2
```

“稳定”要求剩下的 `1、3` 保持原来的先后次序。

如果每遇到一个 2 就调用一次普通删除，后面元素会反复前移。最坏情况下总移动次数为：

$$
(n-1)+(n-2)+\cdots+1=\Theta(n^2)
$$

可以用两个下标只扫描一次：

- `read`：正在检查的旧元素。
- `write`：下一个保留元素应写入的位置，同时等于已保留的元素个数。

遇到要删除的元素，只推进 `read`；遇到要保留的元素，写到 `data[write]`，再推进 `write`。

| `read` | 读到的值 | 操作 | 操作后 `write` | 有效结果前缀 |
|---:|---:|---|---:|---|
| 0 | 2 | 跳过 | 0 | 空 |
| 1 | 1 | 写入 `data[0]` | 1 | `[1]` |
| 2 | 2 | 跳过 | 1 | `[1]` |
| 3 | 3 | 写入 `data[1]` | 2 | `[1,3]` |
| 4 | 2 | 跳过 | 2 | `[1,3]` |

```cpp
void DeleteAllX(SqList &L, ElemType x) {
    int write = 0;
    for (int read = 0; read < L.length; ++read) {
        if (L.data[read] != x) {
            L.data[write] = L.data[read];
            ++write;
        }
    }
    L.length = write;
}
```

为什么覆盖不会破坏尚未读取的元素？整个过程中始终有 `write <= read`，只会写到当前位置或其左边。

结束后，数组后面的旧值可能还存在，但已经不属于逻辑表。只需把 `length` 改成 2，不必把整个数组清零。

每个旧元素检查一次，时间 $\Theta(n)$，辅助空间 $O(1)$；空表、全部删除、一个也不删都适用。

### 13.2 删除一个值域内的元素：先确定保留条件

例如删除闭区间 $[s,t]$ 内的元素，要求 $s\le t$。要保留的条件就是：

$$
data[read]<s\quad\text{或}\quad data[read]>t
$$

```cpp
bool DeleteRange(SqList &L, ElemType s, ElemType t) {
    if (s > t) return false;
    int write = 0;
    for (int read = 0; read < L.length; ++read) {
        if (L.data[read] < s || L.data[read] > t)
            L.data[write++] = L.data[read];
    }
    L.length = write;
    return true;
}
```

这段代码不要求表有序，仍是 $O(n)$ 时间、$O(1)$ 辅助空间。

若表已经递增，待删除元素形成一个连续区间，也可以先找到其左右边界，再把右侧后缀统一前移。即使边界用二分找到，搬移元素通常仍需 $O(n)$，不能把整个删除算法写成 $O(\log n)$。

题目若要求删除开区间 $(s,t)$，保留条件应改成 `<= s || >= t`。边界是否包含必须看题意。

### 13.3 有序表去重：比较最后保留的元素

例如：

```text
[1, 1, 2, 2, 2, 4] → [1, 2, 4]
```

有序表的相同值必然相邻。先保留第一个元素，随后只有遇到一个不同于“最后保留值”的元素才写入。

```cpp
void UniqueSorted(SqList &L) {
    if (L.length == 0) return;
    int write = 1;
    for (int read = 1; read < L.length; ++read) {
        if (L.data[read] != L.data[write - 1])
            L.data[write++] = L.data[read];
    }
    L.length = write;
}
```

`write=1` 表示第一个元素已保留，`write-1` 是最后保留元素的下标。空表必须提前返回，否则这个初值会错误地把空表长度改成 1。

时间 $O(n)$，辅助空间 $O(1)$。

**适用前提是有序。** 对 `[1,2,1]` 使用这段代码不能删去第二个 1。若无序表先排序再去重，虽然可以完成去重，但原有相对次序一般会改变。

### 13.4 合并两个递增顺序表：每次取当前较小者

设：

```text
A = [1, 4, 7]
B = [2, 4, 6]
```

用 `i、j` 分别指向两表当前尚未处理的第一个元素，用 `k` 指向结果表下一空位。

```text
比较 1 与 2 → 取 A 的 1
比较 4 与 2 → 取 B 的 2
比较 4 与 4 → 先取 A 的 4
比较 7 与 4 → 取 B 的 4
比较 7 与 6 → 取 B 的 6
B 用完       → 复制 A 剩下的 7
结果：[1,2,4,4,6,7]
```

```cpp
// C 必须是与 A、B 不同的结果表；容量为 MaxSize。
bool MergeSorted(const SqList &A, const SqList &B, SqList &C) {
    if (A.length + B.length > MaxSize) return false;
    int i = 0, j = 0, k = 0;
    while (i < A.length && j < B.length) {
        if (A.data[i] <= B.data[j]) C.data[k++] = A.data[i++];
        else C.data[k++] = B.data[j++];
    }
    while (i < A.length) C.data[k++] = A.data[i++];
    while (j < B.length) C.data[k++] = B.data[j++];
    C.length = k;
    return true;
}
```

两个表共有 $m+n$ 个元素，各取出一次，时间 $O(m+n)$。结果表占 $O(m+n)$ 空间；如果结果存储不计入辅助空间，则额外下标仅占 $O(1)$。答题时说明采用哪一种口径。

相等时先取 A，可保持各原表内部的次序。若题目要求“合并并去重”，还要加入重复判断，不能直接把这份保留重复值的代码当答案。

### 13.5 逆置与循环左移：三次逆置

**逆置一个区间**：最左与最右交换，两端同时向中间缩小，直到相遇或交错。

```cpp
// 调用者保证非空区间满足 0 <= left <= right < 数组长度。
void ReverseRange(ElemType a[], int left, int right) {
    while (left < right) {
        ElemType temp = a[left];
        a[left] = a[right];
        a[right] = temp;
        ++left;
        --right;
    }
}
```

将长度为 $n$ 的数组循环左移 $p$ 位，例如：

```text
[1,2,3,4,5,6,7] 左移 3 位 → [4,5,6,7,1,2,3]
```

把原表看成两个连续片段：

```text
A = [1,2,3]，B = [4,5,6,7]
目标：AB → BA
```

依次逆置 A、逆置 B、逆置整个表：

```text
[1,2,3 | 4,5,6,7]
[3,2,1 | 4,5,6,7]   逆置 A
[3,2,1 | 7,6,5,4]   逆置 B
[4,5,6,7 | 1,2,3]   整体逆置
```

整体逆置同时交换了两段的位置，并把各段内部的逆序恢复了。因此最终是 BA，每段内部次序不变。

```cpp
void RotateLeft(SqList &L, int p) {
    int n = L.length;
    if (n == 0) return;           // 防止对 0 取模
    p = (p % n + n) % n;          // 统一到 [0,n-1]
    if (p == 0) return;
    ReverseRange(L.data, 0, p - 1);
    ReverseRange(L.data, p, n - 1);
    ReverseRange(L.data, 0, n - 1);
}
```

时间 $O(n)$，辅助空间 $O(1)$。若题目限定 $0<p<n$，归一化部分可省略。循环右移 $p$ 位可转成左移 $n-p$ 位。

这也是交换两个相邻片段的通用方法；只要得到前一段的长度，就能使用同样的三次逆置。

### 13.6 主元素：先抵消，再验证

教材中的“主元素”指出现次数**超过** $n/2$ 的元素。出现次数恰为一半不满足条件。因为两种不同值的出现次数不可能都超过一半，所以主元素至多一个。

抵消法的依据：从序列中删去一对不同的元素，如果原序列有主元素，这一主元素在剩余非空序列中仍占多数。每次抵消至多同时删去它的一次出现和另一个值的一次出现，优势不会被反转。

维护：

- `candidate`：当前候选值。
- `count`：当前未被抵消的候选个数。

读到相同值，`count++`；读到不同值，`count--`；当 `count==0`，下一元素成为新候选。

```text
序列：[2,1,2,3,2,2,4]
读 2：候选 2，count=1
读 1：抵消，count=0
读 2：候选 2，count=1
读 3：抵消，count=0
读 2：候选 2，count=1
读 2：count=2
读 4：count=1
```

最后候选是 2，再数一次实际出现次数为 4，满足 $4>7/2$。

```cpp
bool FindMajority(const SqList &L, ElemType &answer) {
    if (L.length == 0) return false;
    ElemType candidate = 0;
    int count = 0;
    for (int i = 0; i < L.length; ++i) {
        if (count == 0) {
            candidate = L.data[i];
            count = 1;
        } else if (L.data[i] == candidate) {
            ++count;
        } else {
            --count;
        }
    }
    int occurrences = 0;
    for (int i = 0; i < L.length; ++i)
        if (L.data[i] == candidate) ++occurrences;
    if (occurrences <= L.length / 2) return false;
    answer = candidate;
    return true;
}
```

第一轮得到的是候选，不保证存在主元素。例如 `[1,2,3]` 最后也会留下候选，但没有任何值超过一半，所以第二轮验证不能省。

两轮扫描仍是 $O(n)$ 时间，辅助空间 $O(1)$。

### 13.7 最小未出现正整数：只需标记 $1$ 到 $n$

例如：

```text
[-2,3,1,5] → 最小未出现正整数为 2
```

长度为 $n$ 的数组，答案一定在 $[1,n+1]$ 内：

- 如果 $1$ 到 $n$ 都出现，答案是 $n+1$。
- 否则，这 $n$ 个正整数中至少有一个未出现，答案不超过 $n$。

所以负数、0、大于 $n$ 的值都不用标记。

```cpp
#include <vector>

int SmallestMissingPositive(const SqList &L) {
    int n = L.length;
    std::vector<unsigned char> seen(n + 1, 0);
    for (int i = 0; i < n; ++i) {
        int x = L.data[i];
        if (x >= 1 && x <= n) seen[x] = 1;
    }
    for (int x = 1; x <= n; ++x)
        if (seen[x] == 0) return x;
    return n + 1;
}
```

例子中 $n=4$，只标记 1 和 3；从 1 开始检查，第一个未标记值是 2。

时间 $O(n)$，辅助空间 $O(n)$。这是一份保持原数组的标记解法；若题目要求 $O(1)$ 辅助空间，需要改用原地交换等方法，不能沿用额外标记数组却把空间写成 $O(1)$。

### 13.8 两个等长有序数组的中位数：先认清所求名次

本类教材题把合并后 $2n$ 个元素中的**第 $n$ 小元素**定义为中位数，即较小的那个中间元素。它与统计学中常见的“两个中间元素取平均”不是同一个约定，必须看题目定义。

例如：

```text
A=[1,3,5]，B=[2,4,6]
合并序列=[1,2,3,4,5,6]
第 n=3 小元素是 3
```

直观方案：像有序合并一样，每次取较小者，取到第 $n$ 个就返回。时间 $O(n)$，只维护指针与当前值，辅助空间 $O(1)$，不必真正建立结果数组。

要进一步减少时间，可以把问题推广成“两个有序数组的第 $k$ 小元素”。每轮比较两边约第 $k/2$ 个尚未处理的元素，舍弃端点较小的那段前缀，并减少 $k$。

为什么能够舍弃？设两侧本轮各取的前缀长度为 $u,v$，都有 $u,v\le\lfloor k/2\rfloor$。若 A 的比较端点不大于 B 的端点，则 A 的这 u 个元素排在当前目标之前：在 B 中只有该端点之前的至多 $v-1$ 个元素可能排在 A 端点前面，所以端点的名次至多为 $u+v-1<k$。相等时按 A 在先的次序处理即可。删去这 u 个元素后，原第 k 小元素变成剩余序列的第 $k-u$ 小元素；这些被删元素不必恰好是全局最小的 u 个。

```cpp
#include <algorithm>

// A、B 递增，1 <= k <= m+n；返回第 k 小的值。
ElemType KthTwoSorted(const ElemType A[], int m,
                      const ElemType B[], int n, int k) {
    int i = 0, j = 0;
    while (true) {
        if (i == m) return B[j + k - 1];
        if (j == n) return A[i + k - 1];
        if (k == 1) return std::min(A[i], B[j]);
        int takeA = std::min(k / 2, m - i);
        int takeB = std::min(k / 2, n - j);
        if (A[i + takeA - 1] <= B[j + takeB - 1]) {
            i += takeA;
            k -= takeA;
        } else {
            j += takeB;
            k -= takeB;
        }
    }
}
```

对上面的 A、B，最初 $k=3$：比较 1、2，舍弃 A 的 1，变成找剩余元素中的第 2 小；再比较 3、2，舍弃 B 的 2，变成找剩余元素中的第 1 小，结果为 `min(3,4)=3`。

通常每轮至少将 $k$ 缩小约一半；某一侧剩余不足 $k/2$ 个且被舍弃时，这一侧直接耗尽。时间 $O(\log(m+n))$，辅助空间 $O(1)$。等长中位数调用时令 `m=n`、`k=n`，并要求 $n>0$。

### 13.9 三个有序数组的最小距离：每次推进最小值

从三个递增数组中各取一个值 $a,b,c$，距离定义为：

$$
D=|a-b|+|b-c|+|c-a|
$$

将三值从小到大写成 $x\le y\le z$，则：

$$
D=(y-x)+(z-y)+(z-x)=2(z-x)
$$

问题就变成缩小当前三元组的最大值与最小值之差。

三个指针开始都在数组首元素处。每轮计算距离，然后推进当前最小值所在的指针。固定最小值而推进其他指针，其他值只会增大或不变，不能得到更小的范围；因此要寻找改进，就应让最小值向右移动。

```cpp
// 三个数组非空且递增；用 long long 计算差，避免 int 减法溢出。
bool MinTripleDistance(const int A[], int m, const int B[], int n,
                       const int C[], int p, long long &answer) {
    if (m <= 0 || n <= 0 || p <= 0) return false;
    int i = 0, j = 0, k = 0;
    bool first = true;
    while (i < m && j < n && k < p) {
        long long a = A[i], b = B[j], c = C[k];
        long long low = std::min(a, std::min(b, c));
        long long high = std::max(a, std::max(b, c));
        long long distance = 2 * (high - low);
        if (first || distance < answer) {
            answer = distance;
            first = false;
        }
        if (distance == 0) break; // 不可能比 0 更小
        if (a == low) ++i;
        else if (b == low) ++j;
        else ++k;
    }
    return true;
}
```

例如三表分别为 `[1,4]、[2,5]、[3,6]`：先比较 `(1,2,3)`，距离为 4；推进 1 后得到 `(4,2,3)`，距离仍为 4；再推进 2，继续检查 `(4,5,3)`。每一步只推进一个指针。

任一数组耗尽即停止：若想继续保留该数组最后一个值，其他数组向右走只会增大当前上界，不能改善此前已经检查的距离。

时间 $O(m+n+p)$，辅助空间 $O(1)$。这里利用的是三个输入数组各自有序，不能把同样的推进规则用于无序数组。

### 13.10 本部分的方法地图

| 题目特征 | 优先考虑的办法 | 需要守住的条件 |
|---|---|---|
| 原地删除，保留相对次序 | 读写双指针 | 最后更新逻辑长度 |
| 有序表去重 | 比较最后保留值 | 空表、相同值相邻 |
| 两个有序表合并 | 两指针选较小值 | 结果容量、重复值约定 |
| 原地交换连续片段、循环移位 | 三次逆置 | 下标边界、空表不能取模 |
| 出现次数超过一半 | 候选抵消 + 二次验证 | “超过”，不是“等于” |
| 最小未出现正整数 | 限定候选范围 + 标记 | 额外标记数组计入空间 |
| 两个有序数组的第 $k$ 小 | 合并计数或折半排除 | 名次从 1 开始 |
| 三有序数组最小距离 | 推进当前最小值 | 距离公式、有序性 |

## 第十四部分：链表综合算法

这一部分结合教材 2.3 综合习题和旧文档中的算法。默认是**带头结点、以空指针结束的单链表**；除了判环题，输入均无环。存在共享结点时，删除或改链可能影响另一条表，不能套用要求两表独立的算法。

### 14.1 删除所有值为 $x$ 的结点：保留前驱

设：

```text
L → 头 → 2 → 2 → 1 → 2 → NULL
```

用 `pre` 指向待检查结点的前驱。若 `pre->next` 是目标值，则摘除并释放它，**`pre` 保持不动**；下一轮检查它的新后继。若不是目标值，才让 `pre` 前进。

```cpp
void DeleteLinkAllX(LinkList L, ElemType x) {
    if (L == nullptr) return;
    LNode *pre = L;
    while (pre->next != nullptr) {
        LNode *q = pre->next;
        if (q->data == x) {
            pre->next = q->next;
            std::free(q);
        } else {
            pre = q;
        }
    }
}
```

逐步看连续的两个 2：

```text
pre=头，删第一个 2 → 头 → 2 → 1 → 2
pre仍为头，删第二个2 → 头 → 1 → 2
遇到1不删，pre移到1 → 头 → 1 → 2
删1后面的2         → 头 → 1 → NULL
```

若删除后同时推进 `pre`，就可能跳过连续目标结点；若先 `std::free(q)` 再读 `q->next`，就使用了已释放的内存。

每个结点处理一次，时间 $O(n)$，辅助空间 $O(1)$。头结点不参与数据比较，也不释放。

### 14.2 单链表原地逆置：保存后继，再头插

目标：

```text
头 → 1 → 2 → 3 → NULL
变为
头 → 3 → 2 → 1 → NULL
```

先让 `p` 保存旧首元结点，再把头结点后的链置空。依次取出旧链结点，头插到新链。

```cpp
void ReverseLinkList(LinkList L) {
    if (L == nullptr) return;
    LNode *p = L->next;
    L->next = nullptr;
    while (p != nullptr) {
        LNode *q = p->next;       // 先保存旧链的下一结点
        p->next = L->next;       // p 接到新链头部
        L->next = p;
        p = q;                   // 回到旧链继续处理
    }
}
```

| 取出的结点 | 逆置后已完成部分 | 旧链尚未处理部分 |
|---|---|---|
| 尚未取出 | 空 | `1→2→3` |
| 1 | `1` | `2→3` |
| 2 | `2→1` | `3` |
| 3 | `3→2→1` | 空 |

`q=p->next` 必须在改写 `p->next` 前执行，否则会丢失旧链剩余部分。这与基本插入里的“先保护原后继”是同一原则。

时间 $O(n)$，辅助空间 $O(1)$；复用原结点，不申请新结点、不交换数据值。空表和单结点表也适用。

若表结构额外保存尾指针，逆置后尾指针应改为原首元结点；这里的 `LinkList` 类型没有独立尾指针字段。

### 14.3 倒数第 $k$ 个结点：让两指针相隔 $k$ 步

链表只能向后走，不能像数组一样直接访问 `data[n-k]`。可以让 `fast、slow` 都从首元结点开始，先让 `fast` 走 $k$ 步，再同步前进。

```text
1 → 2 → 3 → 4 → 5 → NULL，k=2
```

| 阶段 | `slow` | `fast` |
|---|---|---|
| 开始 | 1 | 1 |
| fast 先走 2 步 | 1 | 3 |
| 同步第 1 步 | 2 | 4 |
| 同步第 2 步 | 3 | 5 |
| 同步第 3 步 | 4 | NULL |

`fast` 走到空指针时，`slow` 后面恰有 $k-1$ 个数据结点，所以 `slow` 是倒数第 $k$ 个。

```cpp
LNode *KthFromEnd(LinkList L, int k) {
    if (L == nullptr || k <= 0) return nullptr;
    LNode *slow = L->next;
    LNode *fast = L->next;
    for (int step = 0; step < k; ++step) {
        if (fast == nullptr) return nullptr; // 不足 k 个结点
        fast = fast->next;
    }
    while (fast != nullptr) {
        slow = slow->next;
        fast = fast->next;
    }
    return slow;
}
```

边界逐项代入：

- $k=1$：返回尾结点。
- $k=n$：`fast` 预走后已经为空，返回首元结点。
- $k>n$：预走阶段发现空指针，返回空。
- $k\le0$ 或空表：返回空。

时间 $O(n)$，辅助空间 $O(1)$。这是一趟向前扫描，没有先求长度再重扫；`slow` 只是滞后跟随同一方向。

### 14.4 中间结点：先约定偶数长度取哪一个

中点问题中，快指针一次走两步，慢指针一次走一步。初始化不同，偶数长度时的结果也不同。

下面取偶数长度的**前一个中点**：

```text
1→2→3→4→5，返回3
1→2→3→4，返回2
```

```cpp
LNode *FirstMiddle(LinkList L) {
    if (L == nullptr || L->next == nullptr) return nullptr;
    LNode *slow = L->next;
    LNode *fast = slow->next;
    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow;
}
```

长度 4 时，开始 `slow=1、fast=2`；同步一次得到 `slow=2、fast=4`。因为 4 没有后继，循环结束，返回 2。

若 `fast` 也从首元结点开始，同样的循环会在长度 4 时返回 3，即后一个中点。两种写法都可用，但必须与切分任务的要求对应。

时间 $O(n)$，辅助空间 $O(1)$。判定先检查 `fast`，再检查 `fast->next`，利用短路求值避免访问空指针。

### 14.5 两条无环单链表的首个公共结点：比较地址

公共结点表示两条表真正共享同一块结点内存。例如：

```text
A：头A → 1 → 2 ┐
              7 → 8 → NULL
B：头B → 3 ───┘
```

一旦两条单链表到达同一结点，其后继链接就是同一个，因此后面整段必然共享。

两个值都为 7，不一定是公共结点。需要判断 `p==q`，而不是 `p->data==q->data`。

因为共享后缀长度相同，先求两表长度，让较长表的指针先走长度差，再同步前进。这样两指针距离各自表尾的步数始终相同。

```cpp
LNode *FirstCommonNode(LinkList A, LinkList B) {
    if (A == nullptr || B == nullptr) return nullptr;
    int lenA = LinkLength(A), lenB = LinkLength(B);
    LNode *p = A->next;
    LNode *q = B->next;
    while (lenA > lenB) { p = p->next; --lenA; }
    while (lenB > lenA) { q = q->next; --lenB; }
    while (p != q) {
        p = p->next;
        q = q->next;
    }
    return p;  // 相遇于公共结点，或同时到 NULL
}
```

例子中 A 有 4 个数据结点，B 有 3 个。A 先走一步到 2，B 仍在 3；随后同步一步，两者都到共享的 7。

时间 $O(m+n)$，辅助空间 $O(1)$，不改动链接。输入必须无环；有环时长度与“对齐到表尾”的依据都不成立。

本题只查找共享位置。不能分别调用普通销毁函数释放两表的共享后缀，否则同一结点可能被释放两次。

### 14.6 合并两个递增链表：摘取并复用原结点

输入两条独立链表：

```text
A：头A → 1 → 4 → 7 → NULL
B：头B → 2 → 4 → 6 → NULL
```

结果保留 A 的头结点，数据链合为 `1→2→4→4→6→7`，B 留下空头结点。

先用 `p、q` 保存两表原首元结点，再让两个头结点后的链接置空。用 `r` 作为结果尾指针，每次把较小结点接到 `r` 后面。

```cpp
// A、B 带头结点、各自递增、无环，且不共享数据结点。
// 成功后 A 保存合并结果，B 为空表；两头结点仍保留。
bool MergeSortedNodes(LinkList A, LinkList B) {
    if (A == nullptr || B == nullptr || A == B) return false;
    LNode *p = A->next;
    LNode *q = B->next;
    A->next = nullptr;
    B->next = nullptr;
    LNode *r = A;
    while (p != nullptr && q != nullptr) {
        if (p->data <= q->data) {
            r->next = p;
            p = p->next;
        } else {
            r->next = q;
            q = q->next;
        }
        r = r->next;
    }
    r->next = (p != nullptr) ? p : q;
    return true;
}
```

为什么能直接接上剩余链？当一条表用完时，另一条表的剩余部分已经有序，且都不小于刚接入的尾结点，无须逐个重新比较。

时间 $O(m+n)$，辅助空间 $O(1)$，不申请数据结点。它会改变原链接：合并后不能再把 B 当作保存原序列的表使用。

若两表共享数据结点，算法可能把同一结点接入两次并形成环，所以独立性是输入前提。仅检查 `A!=B` 不等于已经验证没有共享结点。

**变式：递增输入，递减输出。** 仍逐个摘取当前较小结点，但把它头插到结果表，最后顺序自然反转。注意剩余链也要逐结点头插，不能整段尾接。

**变式：求有序表交集。** `p` 小就推进 `p`，`q` 小就推进 `q`，相等时输出并同时推进。重复值要按题目判断：按多重集合输出，还是每种值只输出一次。

### 14.7 判环与环入口：快慢指针为何有效

这里处理普通单链表中可能存在的异常环，例如：

```text
1 → 2 → 3 → 4 → 5
        ↑       ↓
        └───────┘
```

环入口是 3。普通无环表应以 `NULL` 结束；本题要判断是否存在沿 `next` 一直走都无法到达空指针的情况。

**第一阶段：判断是否有环。** 慢指针每次走一步，快指针每次走两步。

- 无环时，快指针最终到达空指针或尾结点。
- 有环时，两者都进入环后，快指针相对慢指针每轮多走一步；相对位置在有限个环结点上循环变化，最终必相遇。

**第二阶段：找到入口。** 相遇后，一个指针重新从首元结点出发，另一个留在相遇处；两者每次都走一步，再次相遇处就是入口。

设从首元结点到环入口的距离为 $a$，环长为 $c$，入口沿环到首次相遇位置的距离为 $b$。第一次相遇时慢指针走了 $t$ 步，快指针走了 $2t$ 步，两者步数差是若干整圈：

$$
t\equiv0\pmod c
$$

而慢指针到相遇处满足 $t\equiv a+b\pmod c$，所以：

$$
a+b\equiv0\pmod c
$$

从相遇点再走 $a$ 步，沿环的位置为 $b+a\equiv0\pmod c$，正好回到入口；从首元结点走 $a$ 步也正好到入口。

```cpp
LNode *CycleEntry(LinkList L) {
    if (L == nullptr) return nullptr;
    LNode *first = L->next;
    LNode *slow = first;
    LNode *fast = first;
    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            LNode *p = first;
            while (p != slow) {
                p = p->next;
                slow = slow->next;
            }
            return p;
        }
    }
    return nullptr;
}
```

必须在移动后比较 `slow==fast`。两者初始位置相同不说明有环。

时间 $O(n)$，辅助空间 $O(1)$，这里 $n$ 是能够到达的不同结点数。算法不破坏链接。

第十部分的循环链表本来就设计成有环。不能把“检测到环”直接解释为该循环链表出错；本题讨论的是普通单链表的约定。

### 14.8 首尾交替重排：找中点、逆后半、交替合并

目标模式：

$$
a_1,a_2,\ldots,a_n
\quad\longrightarrow\quad
a_1,a_n,a_2,a_{n-1},\ldots
$$

例如：

```text
1→2→3→4→5 → 1→5→2→4→3
1→2→3→4   → 1→4→2→3
```

单链表不能从尾部反复向前走，可以把题目拆成三个已学操作：

1. 找前一个中点，切成前、后两段。
2. 逆置后半段，让尾部元素可以从前往后取。
3. 前半段取一个，后半段取一个，交替接入。

长度 5 的演算：

```text
原表：1→2→3→4→5
切分：1→2→3  和  4→5
逆后：1→2→3  和  5→4
交替：1→5→2→4→3
```

```cpp
// 逆置一段不带头结点的链，返回新首结点。
LNode *ReverseChain(LNode *first) {
    LNode *prev = nullptr;
    while (first != nullptr) {
        LNode *next = first->next;
        first->next = prev;
        prev = first;
        first = next;
    }
    return prev;
}

void ReorderEnds(LinkList L) {
    if (L == nullptr || L->next == nullptr) return;
    LNode *middle = FirstMiddle(L);
    LNode *second = middle->next;
    middle->next = nullptr;       // 先断开，两段独立
    second = ReverseChain(second);
    LNode *first = L->next;
    while (second != nullptr) {
        LNode *nextFirst = first->next;
        LNode *nextSecond = second->next;
        first->next = second;
        second->next = nextFirst;
        first = nextFirst;
        second = nextSecond;
    }
}
```

前半段长度不少于后半段，后半段每次取一个时，前半段必有一个结点与其配对。奇数长度多出的中点自然留在表尾。

切分时的 `middle->next=nullptr` 不能省：若两段仍保持旧链接，逆置、拼接后可能形成环。交替连接前也必须分别保存两个原后继。

三段操作各扫描至多 $n$ 个结点，总时间 $O(n)$，辅助空间 $O(1)$，复用原结点。

### 14.9 按绝对值去重：标记与删除结合

若题目规定结点值的绝对值不超过 $M$，要求只保留每种绝对值第一次出现的结点，则：

```text
3→-3→2→-2→4 → 3→2→4
```

这里 3 与 -3 视为重复，和普通按原值去重的判断不同。

申请 `seen[0..M]`，用绝对值作为下标。扫描时仍维护前驱 `pre`：未见过就标记并前进，见过就删除当前后继，前驱保持不动。

```cpp
// 输入保证所有结点值的绝对值 <= M，M >= 0。
void UniqueByAbs(LinkList L, int M) {
    if (L == nullptr || M < 0) return;
    std::vector<unsigned char> seen(static_cast<std::size_t>(M) + 1, 0);
    LNode *pre = L;
    while (pre->next != nullptr) {
        LNode *q = pre->next;
        long long value = q->data;       // 先扩宽再取负
        long long key = value < 0 ? -value : value;
        if (seen[static_cast<std::size_t>(key)] == 0) {
            seen[static_cast<std::size_t>(key)] = 1;
            pre = q;
        } else {
            pre->next = q->next;
            std::free(q);
        }
    }
}
```

先转为 `long long` 再取负，是为了避免在 `int` 范围内对最小负数直接求负产生溢出。数组下标仍依赖题目给出的 $M$ 上界，不能用于未限制值域的任意输入。

标记数组初始化需 $O(M)$，扫描需 $O(n)$，因此总时间 $O(n+M)$，辅助空间 $O(M)$。不能只看到“一次遍历”就忽略初始化开销。

### 14.10 链表题的解题步骤

**第一步：确认模型。** 是否带头结点？是否循环？是否双向？是否共享结点？值是否有序？

**第二步：选择需要的指针。** 删除通常需要前驱；建立和合并通常需要尾指针；倒数第 $k$ 个需要固定间距；中点和判环需要不同速度。

**第三步：写出每个指针表示什么。** 如“`pre` 始终是待检查结点的前驱”，比只写变量名更能说明算法。

**第四步：改链前保存后继。** 把要继续访问的链用局部指针保存，再修改 `next` 或释放结点。

**第五步：检查空表、单结点、首结点、尾结点。** 尤其检查结束后的尾链接是否正确，是否漏结点、成环、重复释放。

**第六步：分别分析遍历和局部操作。** 一次扫描里每个结点只处理常数次通常是 $O(n)$；循环里反复从头定位可能是 $O(n^2)$；标记数组计入空间及初始化时间。
