## 一、串的定义和基本概念（视频032）

### 1.1 什么是串

**串（String）即字符串**，是由零个或多个字符组成的**有限序列**，一般记为：

$$
S = 'a_1a_2\cdots a_n' \quad (n\ge 0)
$$

- **串名**：字符串变量的名字，如 `S`、`T`
- **串的值**：单引号（或双引号，依语言而定）括起来的字符序列；**引号只是边界符，不是串的内容**
- **串的长度**：串中字符的个数 `n`
- **空串**：长度为 0 的串，两个引号之间什么都没有，记作 `''`

> 视频老师提醒：`S='abcdefghijk'` 的长度是 11，**不能把两个引号算进去**。

### 1.2 子串、主串、位置

| 术语 | 含义 |
|------|------|
| **子串** | 串中**任意连续**字符组成的子序列；空串也是子串；子串一定真实存在于主串中 |
| **主串** | 包含子串的那个完整的串 |
| **字符在主串中的位置** | 该字符在串中的**位序，从 1 开始数**（和线性表位序一致，不是从 0） |
| **子串在主串中的位置** | 以子串**第一个字符**的位置作为整个子串的位置 |

> [!warning] 两个最容易错的点
> 1. **位置/位序从 1 开始**，不是数组下标那种从 0 开始。
> 2. **空格也是一个字符**，占 1 字节。跨考同学尤其注意。

### 1.3 空串 ≠ 空格串（必考辨析）

- **空串**：引号内什么都没有，长度为 **0**。
- **空格串**：引号内是一个或多个空格字符，每个空格都算字符，长度 = 空格个数，**不为 0**。

例如 `M=''` 长度 0；`N='   '`（3 个空格）长度 3。

### 1.4 串和线性表的区别（理解，可能出概念选择题）

串本质上是一种**特殊的线性表**，字符之间也是一对一的线性关系。区别有两点：

1. **数据元素类型受限**：普通线性表的元素可以是任意类型（`ElemType`）；而串的元素**只能是字符**。
2. **操作对象不同**：线性表的增删改查通常针对**单个元素**；串的增删改查通常以**子串（一串连续字符）**为操作对象。

> 视频老师类比：你用搜索引擎时不会只搜一个字母，而是输入一串有意义的字符，让引擎在海量长文本里找出包含这串内容的地方——这就是典型的"以子串为对象"的操作。

## 二、串的基本操作（视频032）

| 操作 | 功能 | 备注 |
|------|------|------|
| `StrAssign(&T, chars)` | 赋值，把字符序列 chars 赋给 T | |
| `StrCopy(&T, S)` | 复制，把串 S 复制给 T | |
| `StrEmpty(S)` | 判空，长度为 0 返回 true | |
| `StrLength(S)` | 求串长 | |
| `ClearString(&S)` | **清空**：逻辑上清空，但**内存不归还**，还能继续用 | 区别于销毁 |
| `DestroyString(&S)` | **销毁**：把存储空间**归还系统**，之后不能再用 | |
| `Concat(&T, S1, S2)` | 连接，用 T 返回 S1 接上 S2 的结果 | 可能需要扩容 |
| `SubString(&Sub, S, pos, len)` | 求子串：从 S 的第 pos 个字符起取 len 个字符给 Sub | |
| `Index(S, T)` | **定位**：返回子串 T 在主串 S 中**第一次出现**的位置，找不到返回 0 | 就是模式匹配 |
| `StrCompare(S, T)` | 比较两串大小，返回正/0/负值 | 见下 |

### 2.1 串的比较规则（重点，选择题常考）

从**第一个字符开始逐个向后比较**：

1. 遇到第一对**不相等**的字符，由这对字符的大小决定整个串的大小——**谁的字符大，谁所在的串就大**，后面不再看。
2. 若前面字符全部相同，则**更长的串更大**（如 `'abstract' < 'abstraction'`）。
3. 只有每个字符都相同**且长度相等**，两串才相等。

字符大小的**本质是比较其编码的二进制数值**：ASCII 中 `'a' < 'c'`，因为 `'a'=01100001`、`'c'=01100011`。这也正是字典（四六级顺序词汇表）排序的原理。

返回值约定：`S>T` 返回**正值**，`S==T` 返回 **0**，`S<T` 返回**负值**（代码里直接用对应字符相减即可）。

> [!note] 清空 vs 销毁（视频专门区分）
> - 清空：内存还在，只是逻辑上把长度置 0；
> - 销毁：`free` 把内存还给系统，这片空间之后不可用。

## 三、字符集与编码（视频032，了解即可）

计算机只能存二进制，所以要给每个字符规定一个二进制编号：

- **字符集**是"字符的集合"（定义域），**编码**是"字符→二进制"的映射规则（函数 f）。
- **ASCII**：英文世界用，1 字符 = 1 字节（8 bit，256 种状态）；空格的 ASCII 是 `00100000`（即十进制 32）。
- 中文有数万字，1 字节不够，于是有 **Unicode 字符集**，配合 **UTF-8 / UTF-16** 等不同编码；UTF-8 下一个汉字通常占 3 字节。
- **乱码的成因**：存的时候用编码 f，读的时候却用了另一套编码 g 去反解，映射对不上就乱码（相当于用 $g^{-1}$ 去解 $f(x)$）。

> [!note] 考研口径
> 408 数据结构里**默认每个字符占 1 字节**（只考虑英文字符），字符集编码属于拓展常识，知道"空串/空格串、字符按编码比大小"即可。

## 四、串的存储结构（视频033）

串是特殊线性表，所以线性表的三种存储方式串都能用。

### 4.1 顺序存储

#### （1）定长顺序存储（静态数组）

```c
#define MAXLEN 255          // 串的最大容量
typedef struct {
    char ch[MAXLEN];       // 静态数组，每个字符占1字节
    int length;            // 串的实际长度
} SString;
```

缺点：容量固定、存不下就无法扩展（和静态顺序表一样）。

#### （2）堆分配存储（动态数组）

```c
typedef struct {
    char *ch;              // 指向malloc申请的连续空间（堆区）
    int length;
} HString;
```

用 `malloc` 申请、用完要手动 `free`；长度可动态增长，是更灵活的顺序存储。

### 4.2 记录串长的三种方案（选择题考点）

| 方案 | 做法 | 优缺点 |
|------|------|--------|
| ① 单独 length 变量 | 用一个 int 记长度 | 直观、求长 O(1)；王道代码采用其变体 |
| ② 用 `ch[0]` 存长度 | 首位充当 length | **位序与下标一一对应**，但 char 只 1 字节，串长**不能超过 255** |
| ③ 末尾加 `'\0'` | 不存长度，靠结束符判断 | 省空间，但求长度要**从头扫描**，O(n) |

> [!important] 王道的统一约定（本套代码照此实现）
> **废弃 `ch[0]` 不用（字符从 `ch[1]` 开始存），另设一个 int 型 `length` 记录长度。**
> 这样位序和下标只差固定的 1，又不受 255 的长度限制。之后所有代码默认字符**从下标 1 开始**。

### 4.3 链式存储（块链）

每个结点存字符、用指针相连。但 1 字符只占 1 字节、指针在 32 位机占 4 字节，**存储密度极低**。

改进：让**每个结点存多个字符**（块），最后一块存不满用 `#` 或 `'\0'` 填充，以提高存储密度。

> [!note] 优缺点（可能出简答/选择）
> 顺序存储：支持**随机存取**，但插入删除、扩容不便；块链：插删方便，但**不能随机存取**、存储密度低。**408 中串的链式存储几乎不考代码，了解概念即可。**

## 五、顺序串的基本操作实现（视频033）

下面代码基于王道约定：`ch[0]` 废弃、字符从 `ch[1]` 开始、`length` 记长度。

### 5.1 求子串 SubString

```c
// 求子串：用 Sub 返回 S 中从第 pos 个字符起、长度为 len 的子串
bool SubString(SString &Sub, SString S, int pos, int len) {
    if(pos + len - 1 > S.length)   // ★★★★ 子串范围越界检查
        return false;
    for(int i = pos; i < pos + len; i++)
        Sub.ch[i - pos + 1] = S.ch[i];   // 复制到 Sub，仍从下标1开始
    Sub.length = len;
    return true;
}
```

### 5.2 比较操作 StrCompare

```c
// 比较两个串：S>T返回正值，相等返回0，S<T返回负值
int StrCompare(SString S, SString T) {
    for(int i = 1; i <= S.length && i <= T.length; i++) {
        if(S.ch[i] != T.ch[i])
            return S.ch[i] - T.ch[i];   // ★★★★ 第一对不同字符决定大小
    }
    // 前面全部相同，更长的串更大
    return S.length - T.length;        // 长度差：正/0/负
}
```

### 5.3 定位操作 Index（复用上面两个基本操作）

思路：从主串每个候选位置 `i` 起，用 `SubString` 取出与模式串等长的子串，再用 `StrCompare` 比较是否相等。

```c
// 定位：返回子串 T 在主串 S 中第一次出现的位置，找不到返回 0
int Index(SString S, SString T) {
    int n = S.length, m = T.length;
    SString sub;
    for(int i = 1; i + m - 1 <= n; i++) {     // 共 n-m+1 个候选子串
        SubString(sub, S, i, m);             // 取出从 i 起、长 m 的子串
        if(StrCompare(sub, T) == 0)
            return i;                        // 相等，返回起始位置
    }
    return 0;                                // 不存在，返回0
}
```

> [!note] 这个 Index 本质就是朴素模式匹配，只是借助了"取子串 + 比较"两个基本操作。下一节改为直接操作数组下标实现。

## 六、朴素模式匹配算法（视频034）

### 6.1 术语与思想

- **主串 S**：被搜索的长串，长度 `n`；
- **模式串 T**：想找的那段内容，长度 `m`（**模式串不一定能在主串中找到**，这是它和"子串"的区别）。

**暴力思想**：把主串中所有长度为 m 的子串（共 **n−m+1** 个）逐个与模式串整体比较，直到找到第一个完全相等的子串，或全部不匹配（返回 0）。

### 6.2 双指针实现（王道 1 基版本，重点）

设两个扫描指针：`i` 扫主串、`j` 扫模式串，都从 1 开始。

```c
// 朴素模式匹配（BF算法），返回模式串T在主串S中的起始位置，找不到返回0
int Index_BF(SString S, SString T) {
    int i = 1, j = 1;
    while(i <= S.length && j <= T.length) {
        if(S.ch[i] == T.ch[j]) {      // 当前字符相等，两指针同时后移
            i++; j++;
        } else {                      // 失配：主串指针回退到下一子串起点
            i = i - j + 2;            // ★★★★ 回退公式（1基）
            j = 1;                    // ★★★★ 模式串指针回到第1个字符
        }
    }
    if(j > T.length)                  // 模式串全部匹配完，匹配成功
        return i - T.length;          // ★★★★ 返回子串起始位置
    return 0;
}
```

**回退公式推导（务必理解，不要死背）**：失配时 `j` 表示当前已匹配到模式串第 j 个字符，`i-j` 会让 i 回到当前子串起点的**前一个位置**，要让它指向**下一个子串起点**，所以 `i = i-j+2`；同时 `j=1` 从头再来。

### 6.3 时间复杂度

- 最好情况：每次第一个字符就不等，O(n)。
- **最坏情况：O(nm)**。典型场景是主串前 n−1 个字符和模式串前 m−1 个字符全都相同、只在最后一个字符失配（如主串 `'aaaa…aab'`、模式串 `'aaa…ab'`），于是 n−m+1 个子串每个都要比 m 次：

$$
(n-m+1)\times m = O(nm-m^2+m) = O(nm)\quad(\text{因为实际中 } n\gg m)
$$

> [!warning] 朴素算法的根本缺陷
> 主串指针 `i` 会**不断回退（回溯）**，把之前已经比较过、明明已知相等的字符又重新比一遍——这正是 KMP 要消灭的浪费。

## 七、KMP 算法的思想（视频035，本章最难也最核心）

### 7.1 核心观察：失配位置之前的主串内容是"已知"的

朴素算法失配后之所以让主串回退、从下一个子串头开始重比，是因为它"假装不知道"主串前面是什么。

但事实上：**能匹配到第 j 个字符才失配，说明主串失配位置之前的 j−1 个字符一定与模式串前 j−1 个字符完全相等**——这部分信息是确定的、可以利用的。于是可以：

> 失配后**主串指针 i 保持不动（不回溯）**，只让**模式串指针 j 跳到一个合适的位置**继续比较。

该跳到哪，**只由模式串自身决定，与主串无关**。

### 7.2 next 数组：失配后 j 跳到哪

`next[j] = k` 的含义：**当模式串第 j 个字符失配时，让模式串指针跳到第 k 个字符继续比较**，主串 i 不动。

以模式串 `'abaabc'` 为例（视频逐个位置分析的结论）：

| 失配位置 j | next[j] | 依据（已匹配前缀中，最长相等的"真前缀=真后缀"长度） |
|---|---|---|
| 1 | 0 | 第1个字符就失配，只能整体右移、i/j 共同前进 |
| 2 | 1 | 只匹配了1个字符，无可复用前后缀 |
| 3 | 1 | 已匹配 `ab`，无相等真前后缀 |
| 4 | 2 | 已匹配 `aba`，最长相等前后缀是 `a`（长1），跳到 1+1=2 |
| 5 | 2 | 已匹配 `abaa`，最长相等前后缀是 `a`，跳到 2 |
| 6 | 3 | 已匹配 `abaab`，最长相等前后缀是 `ab`（长2），跳到 2+1=3 |

> [!important] next[j] 的本质（一句话）
> 看失配字符**前面**那段已匹配子串 `T[1..j-1]`，找它**最长的相等真前缀与真后缀**，设其长度为 L，则 **`next[j] = L+1`**；找不到时 `next[j]=1`；规定 **`next[1]=0`**。
>
> （真前缀/真后缀：不能取整段本身。）

### 7.3 KMP 匹配主干代码

```c
// KMP模式匹配：next数组已提前求好；返回T在S中的起始位置，找不到返回0
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while(i <= S.length && j <= T.length) {
        if(j == 0 || S.ch[i] == T.ch[j]) {  // j==0 或当前字符相等
            i++; j++;                        // ★ 两指针共同后移（j==0是首字符失配的特殊处理）
        } else {
            j = next[j];                     // ★★★★★ 失配：i不动，j跳到next[j]
        }
    }
    if(j > T.length)
        return i - T.length;
    return 0;
}
```

与朴素算法对照：**只改了两处**——失配时不再 `i=i-j+2`，而是 `j=next[j]`；并对 `j==0`（第一个字符就失配）做"i、j 同时 +1"的特殊处理。主串 i **只增不减，绝不回头**（"好马不吃回头草"）。

### 7.4 时间复杂度

- 求 next 数组（预处理）：**O(m)**
- 匹配过程：主串 i 不回溯，最多走 n 步，**O(n)**
- **合计 O(m+n)**，明显优于朴素的 O(nm)；额外空间 O(m)（next 数组）。

## 八、手算 next 数组（视频036，选择题硬功夫）

### 8.1 两个固定值

- **`next[1] = 0`**（任何模式串都一样）
- **`next[2] = 1`**（任何模式串都一样）

### 8.2 视频推荐的"滑动对齐"手算法（考试最快）

求 `next[j]` 时：

1. 在**失配字符 T[j] 前面**画一条分界线，线左边是已匹配、内容已知的 `T[1..j-1]`；
2. 把模式串**逐步向右滑动**，每滑一步就看分界线**左侧**上下能否对齐相等；
3. 找到**能对齐的最长情况**，此时分界线对准模式串的第 k 个位置，则 `next[j]=k`；
4. 若一直滑到整个模式串都跨过分界线都对不齐，则 `next[j]=1`。

### 8.3 课堂例题

**例1：`'google'`（g o o g l e）**

| j | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 字符 | g | o | o | g | l | e |
| next | 0 | 1 | 1 | 1 | 2 | 1 |

（j=5 时已匹配 `goog`，最长相等前后缀为 `g`，长1 → next[5]=2；其余找不到相等前后缀为 1。）

**例2：`'abab...'` 类（视频第二个练习）**

| j | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 字符 | a | b | a | b | a | a |
| next | 0 | 1 | 1 | 2 | 3 | 4 |

> [!tip] 手算提速
> 考试时直接在草稿上写"字符行 / 下标行"，对每个 j≥3 只盯着 `T[1..j-1]` 数最长相等前后缀长度 L，填 L+1。多练课后题形成肌肉记忆，第一次学不懂很正常，KMP 本来就需要反复。

### 8.4 代码求 next 数组（能看懂、会补全）

```c
// 求模式串T的next数组（王道1基版本）
void GetNext(SString T, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;                       // ★ 固定
    while(i < T.length) {
        if(j == 0 || T.ch[i] == T.ch[j]) {
            i++; j++;
            next[i] = j;               // 相等则next[i]=j
        } else {
            j = next[j];               // 不等则j回退
        }
    }
}
```

## 九、KMP 的进一步优化：nextval（视频037）

### 9.1 为什么还要优化

按 next 跳转后，可能**立刻又失配**。例如 `'abaabc'` 在 j=3（字符 a）失配，`next[3]=1` 让 j 跳到 1——可 T[1] 也是 **a**，而主串当前字符已经确定"不是 a"，所以这次比较**注定失败**，纯属多余。优化思路：**如果跳转目标位置的字符和当前失配字符相同，就应该一步跳到更前面。**

### 9.2 由 next 手算 nextval 的规则（重点）

先求好 next，再从左到右求 nextval，规则：

- **`nextval[1] = 0`**（固定）；
- 对 j≥2：
  - 若 **`T[j] != T[next[j]]`**（跳转处字符与当前字符**不同**，这次比较有意义）→ **`nextval[j] = next[j]`（保持不变）**；
  - 若 **`T[j] == T[next[j]]`**（字符相同，跳过去也必然失配）→ **`nextval[j] = nextval[next[j]]`（继续向前压缩）**。

**例1：`'ababaa'`**

| j | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| T[j] | a | b | a | b | a | a |
| next | 0 | 1 | 1 | 2 | 3 | 4 |
| nextval | 0 | 1 | 0 | 1 | 0 | 4 |

推导：j=3，T[3]=a，T[next[3]]=T[1]=a，相同 → nextval[3]=nextval[1]=0；j=4，T[4]=b，T[2]=b 相同 → nextval[4]=nextval[2]=1；j=5，T[5]=a，T[3]=a 相同 → nextval[5]=nextval[3]=0；j=6，T[6]=a，T[4]=b 不同 → nextval[6]=next[6]=4。

**例2：`'aaaab'`（连续重复字符，优化效果最明显）**

| j | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| T[j] | a | a | a | a | b |
| next | 0 | 1 | 2 | 3 | 4 |
| nextval | 0 | 0 | 0 | 0 | 4 |

### 9.3 代码求 nextval

```c
// 在next基础上求nextval
void GetNextVal(SString T, int nextval[]) {
    int next[MAXLEN];
    GetNext(T, next);                  // 先求next
    nextval[1] = 0;
    for(int j = 2; j <= T.length; j++) {
        if(T.ch[j] == T.ch[next[j]])
            nextval[j] = nextval[next[j]];   // ★ 字符相同，继续向前压缩
        else
            nextval[j] = next[j];            // 字符不同，保留原值
    }
}
```

匹配时代码**一行都不用改**，把 `j=next[j]` 换成 `j=nextval[j]` 即可。nextval 只减少无意义的比较次数，**不改变匹配结果，也不改变 O(m+n) 的渐进复杂度**。

## 十、0 基前缀函数口径（教材补充，防止和题面代码对不上）

王道视频/教材正文用 **1 基 `next`（next[1]=0）**；但很多题、很多资料给的是 **0 基"前缀函数 π"**，两者数值不同，**不是谁错了，而是口径不同**。

0 基下，`π[i]` = 子串 `T[0..i]` 的最长相等**真前缀=真后缀**长度，`π[0]=0`：

```text
BuildPi(P):                  // 0基
    pi[0] = 0
    for i = 1 .. |P|-1:
        j = pi[i-1]
        while j>0 and P[i]!=P[j]: j = pi[j-1]
        if P[i]==P[j]: j++
        pi[i] = j
```

> [!warning] 答题第一要务：先抄题面口径
> 看到代码先判断它是 **1 基 next（next[1]=0）**、**0 基 π（pi[0]=0）**，还是 **nextval**，**全程用同一套口径推到底，绝不能拿背诵的数值直接套**。常见王道 1 基下，对 j≥2 有 `next[j] = π[j-2] + 1` 的对应关系，但考场上建议按题给代码现场推。

### 11.4 易错点清单

1. **位置从 1 开始**，不是从 0；空格也算字符。
2. **空串长度 0，空格串长度非 0**。
3. 朴素算法失配回退是 **`i=i-j+2, j=1`（1 基）**，别写成 `i=i-j+1`。
4. **`next[j]` 只由失配字符前面的 `T[1..j-1]` 决定**，不能把当前失配字符 T[j] 算进去。
5. `next[1]=0`、`next[2]=1` 对任何模式串都成立。
6. KMP **主串指针 i 不回溯，不代表每个主串字符只比较一次**——j 连续回退时，同一个主串字符可能被比较多次。
7. next、nextval、0 基 π **三套数值不能混用**，先认题面口径。
8. **nextval 不是给 next 统一减 1**，而是"字符相同就沿链继续跳"。
9. 匹配成功返回起始位置：1 基 KMP/BF 都是 `i - m`，注意别和 0 基的 `i-m+1` 混。

## 旧版补充：题型训练与复习资料

### 典型题型与解题方法

1. **求数组**：在草稿上写字符、下标、已匹配段三行；逐列求最长边界，最后统一转换口径。
2. **问下次比较位置**：主串指针保持在失配字符，模式指针跳到 `next[j]`；若 `j=0`，下一步两指针共同前进。
3. **比较次数**：按代码逐次记录 `(i,j)`，字符相等和不等都计一次，`j` 连续回退可能对同一主串字符比较多次。
4. **最大滑动距离**：失配于 $j$ 时模式右移 $j-next[j]$；使用 `nextval` 则代入 `nextval[j]`。


### 完整例题与逐步解答

#### 例 1：手算前缀函数

求模式串 `ABABACA` 的 0 基前缀函数 $\pi$。

> [!success]- 展开完整答案
> $\pi[i]$ 表示子串 $P[0..i]$ 的最长相等真前缀/真后缀长度。逐位计算：
>
> | $i$ | 字符 | $P[0..i]$ | 最长边界 | $\pi[i]$ |
> |---:|:---:|---|---|---:|
> | 0 | A | A | 空 | 0 |
> | 1 | B | AB | 空 | 0 |
> | 2 | A | ABA | A | 1 |
> | 3 | B | ABAB | AB | 2 |
> | 4 | A | ABABA | ABA | 3 |
> | 5 | C | ABABAC | 空 | 0 |
> | 6 | A | ABABACA | A | 1 |
>
> 所以
>
> $$
> \boxed{\pi=[0,0,1,2,3,0,1]}.
> $$
>
> 在 $i=5$ 遇到 C 时，候选边界会从长度 3 回退到 $\pi[2]=1$，再回退到 $\pi[0]=0$，直到找不到可继续的相等边界。

#### 例 2：KMP 失配为何不回退主串

用模式串 `ABABAC` 匹配主串 `ABABABAC`。说明第一次在 C 处失配后的跳转和最终匹配位置。

> [!success]- 展开完整答案
> 模式的前缀函数为
>
> $$
> [0,0,1,2,3,0].
> $$
>
> 主串前 5 个字符 `ABABA` 已与模式前 5 个字符匹配，此时主串下标 5 的 `B` 与模式下标 5 的 `C` 失配。已匹配段 `ABABA` 的最长边界长度为 $\pi[4]=3$，所以模式指针从 5 回退到 3，主串指针仍停在下标 5：
>
> ```text
> text:    A B A B A B A C
> pattern:     A B A B A C
> ```
>
> 此时主串 `B` 与模式下标 3 的 `B` 相等，继续匹配 `A C`，最终模式从主串 0 基下标 2 开始匹配成功。
>
> 主串不回退的依据是：前缀函数已经把“刚才匹配成功的文本后缀”与“模式可复用前缀”对应起来，无需重新比较已知相等的字符。


### 做题识别顺序

1. 先确认使用 0 基 $\pi$、1 基 `next` 还是 `nextval`，不要混表。
2. 求 $\pi[i]$ 时只看 $P[0..i]$ 的真前后缀；失配后沿已有 $\pi$ 链回退。
3. 跟踪匹配时记录 `(i,j)`，失配只回退模式指针，主串指针保持。
4. 比较次数题把每次字符相等/不等都计入，同一主串字符可能比较多次。
5. 周期题除看 $n-\pi[n-1]$ 外，还要检查边界非空且能整除总长度。


### 一页记忆

```c
while (j > 0 && text[i] != pattern[j])
    j = pi[j - 1];
if (text[i] == pattern[j])
    ++j;
```

$$
\boxed{T_{KMP}=O(n+m),\qquad S_{KMP}=O(m)}
$$

- $\pi[i]$ 是 $P[0..i]$ 的最长相等真前缀/真后缀长度。
- 常见王道 1 基口径中，`next[1]=0`；对 $j\ge2$，`next[j]=\pi[j-2]+1`。若题目给不同代码，以代码定义为准。
- `nextval` 在回退位置字符仍与当前字符相同时继续跳过，避免必然重复的失配。


### 易错点

- `next[j]` 由 $P[1..j-1]$ 决定，不把当前失配字符算入已匹配段。
- KMP 主串指针不回退，不代表每个主串字符只比较一次。
- `next` 与前缀函数 $\pi$ 的下标和数值不能直接混用。
- `nextval` 不是简单地给每项减 1。
- 匹配成功返回首位置时注意 0 基和 1 基的差异。


### 跨章节/跨科联系

- [[第7章-查找-视频讲解整理]]同样通过预处理降低在线查找代价。
- KMP 的失配跳转可理解为有限状态自动机；计算机网络协议解析与编译器词法分析会用到字符串匹配。
- 前后缀思想也用于周期判断：令 $p=n-\pi[n-1]$；只有同时满足 $\pi[n-1]>0$、$p<n$ 且 $n\bmod p=0$，串才由长度为 $p$ 的较短非空周期重复构成。

### 自测问题

1. KMP 为什么能保证主串指针不回退？
2. `next[j]` 为什么只取决于 `P[1..j-1]`？
3. 0 基前缀函数与 1 基 `next` 如何建立对应关系？
4. `P[j]==P[next[j]]` 时为何可继续跳到 `nextval[next[j]]`？
5. KMP 的最坏时间和辅助空间分别是多少？

> [!question]- 自测问题参考答案
> 1. 失配前已经知道一段文本等于模式前缀；`next/π` 直接给出该段后缀中可复用的最长模式前缀，只移动模式即可继续，主串字符无需重新读取。
> 2. 失配发生在 $P[j]$，真正已经匹配的是 $P[1..j-1]$；可复用边界必须来自这段已知相等内容，不能把尚未匹配成功的 $P[j]$ 算进去。
> 3. 必须先声明口径。常见王道 1 基定义下 `next[1]=0`，$j\ge2$ 时 `next[j]=π[j-2]+1`；0 基实现通常直接把失配长度更新为 `π[j-1]`。
> 4. 若 $P[j]=P[next[j]]$，在 $P[j]$ 失配后跳到该位置仍会拿同一个字符与当前主串字符比较，必然再次失配；`nextval` 继续沿失配链跳过它。
> 5. 预处理模式 $O(m)$，在线扫描主串 $O(n)$，总时间 $O(n+m)$；前缀/next 数组占 $O(m)$ 辅助空间。
