## 一、树的定义和基本术语（视频038）

### 1.1 树的逻辑结构

树是 $n\ge0$ 个结点的**有限集合**，它是递归定义的结构：

- $n=0$ 时是**空树**；
- 非空树有**且仅有一个根结点**，其余结点可分为 $m$ 个**互不相交**的子树，每棵子树又是一棵树。

> [!warning] 树的三个硬性规定（图不是树）
> 1. 除根结点外，**每个结点有且仅有一个前驱（双亲）**；有两个前驱就不是树，是图/网。
> 2. 根结点的子树之间**互不相交**（否则某结点会出现两个前驱）。
> 3. 只有根结点无前驱；叶子结点无后继。

典型应用：行政区划、电脑文件系统、思维导图。

### 1.2 基本术语（选择题直接考概念）

| 术语 | 含义 |
|------|------|
| **祖先/子孙** | 沿双亲链一路上行/下行的结点 |
| **双亲（父结点）** | 结点的直接前驱；**孩子**是直接后继 |
| **兄弟** | 同一双亲的孩子之间互为兄弟 |
| **堂兄弟** | 同一层（深度相同）的结点；做题时"堂兄弟"= 同层 |
| **路径/路径长度** | 树中的路径**只能从上往下**（边是有向的）；路径长度 = 经过的**边数** |
| **层次/深度** | 从上往下数，**默认从 1 开始**（题目说从 0 开始则另算） |
| **高度** | 从下往上数（叶子高度 1），树的高度 = 层数 |
| **结点的度** | 该结点**孩子**的个数（几个分支） |
| **树的度** | 所有结点度中的**最大值** |
| **分支/非终端结点** | 度 > 0 的结点；**叶子/终端结点**是度 = 0 |
| **有序树/无序树** | 子树从左到右是否有次序（家谱是有序树） |
| **森林** | $m$ 棵**互不相交**的树；也允许**空森林**（m=0） |

> [!note] 视频提醒
> 摇摇车神曲"爸爸的爸爸叫什么"就是祖先链；**路径只能向下**，所以"从子结点到父结点"没有路径，做路径长度题时注意方向。

## 二、树的性质（视频039，选择题高频）

### 2.1 结点数 = 总度数 + 1

每个孩子头上都有一条"天线"（分支），**只有根结点没有天线**，所以：

$$
n = \sum(\text{各结点度数}) + 1 = \text{总边数} + 1
$$

### 2.2 度为 m 的树 vs m 叉树（易混辨析）

| | 度为 m 的树 | m 叉树 |
|---|---|---|
| 结点度数上限 | 每个结点 ≤ m，且**至少有一个结点度 = m** | 每个结点 ≤ m |
| 可否为空树 | **不能**（至少 m+1 个结点） | **可以**（m 叉空树） |
| 结点数下限（高 h） | $h+m-1$ | $h$（一条链） |

> [!warning] 视频强调 + 教材口径
> 度为 m 的树**至少要有 m+1 个结点**（1 个度为 m 的结点 + 它的 m 个孩子）；"高 h 的度为 m 的树最少结点数"教材口径为 $h+m-1$，视频口播说成"h+m+1"，**以教材 $h+m-1$ 为准**。

### 2.3 各层结点数上界

度为 m 的树第 $i$ 层最多 $m^{i-1}$ 个结点；高度为 $h$ 的 m 叉树最多

$$
\frac{m^h-1}{m-1}
$$

个结点（等比数列求和：$1+m+m^2+\cdots+m^{h-1}$）。

### 2.4 最小高度

有 $n$ 个结点的 m 叉树，最小高度：

$$
h=\lceil\log_m(n(m-1)+1)\rceil
$$

推法：$h$ 层的 m 叉树至多 $\frac{m^h-1}{m-1}$ 个结点，$h-1$ 层至多 $\frac{m^{h-1}-1}{m-1}$ 个结点，则

$$
\frac{m^{h-1}-1}{m-1} < n \le \frac{m^h-1}{m-1}
$$

两边乘 $(m-1)$、加 1、取对数即得。

## 三、二叉树的定义和基本术语（视频040）

### 3.1 定义

二叉树是 $n\ge0$ 个结点的有限集合，**递归定义**：空二叉树，或由**根结点 + 左子树 + 右子树**组成，左右子树又各是一棵二叉树。

关键特性：
- 每个结点**至多两棵子树**，且**左右不能颠倒**（有序树）；
- 允许只有左子树、只有右子树、或都空——共**五种基本形态**。

> [!warning] 二叉树 ≠ 度为 2 的有序树
> 度为 2 的有序树要求**至少有一个结点度为 2**；而二叉树允许空树、允许度 1 的结点。二者对"空子树位置"的认定不同。

### 3.2 满二叉树（★必记）

高为 $h$ 的满二叉树结点数为 $\boxed{2^h-1}$：

- 只有最下层有叶子；
- 不存在度为 1 的结点（结点度要么 0 要么 2）；
- 按"从上到下、从左到右、从 1 编号"后：编号 $i$ 的结点，**左孩子 $2i$，右孩子 $2i+1$，双亲 $\lfloor i/2\rfloor$**。

### 3.3 完全二叉树（★★★★ 选择题第一高频）

把满二叉树**从右往左、从下往上删掉若干编号最大的结点**，剩下的就是完全二叉树——即结点编号与满二叉树**一一对应**。

性质（全部要会推）：
1. **叶子只可能出现在最后两层**；
2. **最多只有一个度为 1 的结点**，且该结点**只可能有左孩子**；
3. 编号 $i$ 的结点：左孩子 $2i$、右孩子 $2i+1$、双亲 $\lfloor i/2\rfloor$（与满二叉树相同）；
4. 有 $n$ 个结点的完全二叉树：$i\le\lfloor n/2\rfloor$ 为分支结点，$i>\lfloor n/2\rfloor$ 为叶子。

> [!note] 为什么"度 1 结点只可能是左孩子"？
> 完全二叉树的结点"从左往右结"，某个结点若有右孩子却无左孩子，中间就断档了，编号对不上满二叉树。

### 3.4 二叉排序树与平衡二叉树（本章只要求概念，细节在第7章）

- **二叉排序树（BST）**：左子树所有关键字 < 根 < 右子树所有关键字，左右子树也是 BST；中序遍历 BST 得到递增序列。
- **平衡二叉树（AVL）**：任一结点的左、右子树**高度差不超过 1**；目的是让树"往宽里长"，降低查找比较次数。

## 四、二叉树的性质（视频041，★★★ 必会推导）

### 4.1 核心公式：$n_0 = n_2 + 1$

设度 0、1、2 的结点数分别为 $n_0,n_1,n_2$，结点总数 $n=n_0+n_1+n_2$；又由"结点数=总度数+1"得 $n=n_1+2n_2+1$。两式相减：

$$
\boxed{n_0=n_2+1}
$$

（叶子比二度结点多一个——**选择题用得比吃饭还频繁**。）

### 4.2 层数与总数上界

- 第 $i$ 层最多 $2^{i-1}$ 个结点；
- 高 $h$ 的二叉树最多 $2^h-1$ 个结点（恰好为满二叉树）。

### 4.3 完全二叉树的高度

含 $n$ 个结点的完全二叉树高度：

$$
h=\lceil\log_2(n+1)\rceil=\lfloor\log_2 n\rfloor+1
$$

（推导：$2^{h-1}\le n\le 2^h-1$，两边取对数。）

### 4.4 由 n 推出 n0、n1、n2（★★★ 常见选择题）

完全二叉树 $n_1$ 只可能是 **0 或 1**；且 $n_0+n_2=2n_2+1$ 是**奇数**，则：

| n 的奇偶 | n1 | 结论 |
|---|---|---|
| $n$ 为偶数 | $n_1=1$ | $n_0=n/2$，$n_2=n/2-1$ |
| $n$ 为奇数 | $n_1=0$ | $n_0=(n+1)/2$，$n_2=(n-1)/2$ |

例如 $n=1000$：$n_0=500$，$n_1=1$，$n_2=499$。

## 五、二叉树的存储结构（视频042）

### 5.1 顺序存储

用数组存结点 + `isEmpty` 标志位，把结点按完全二叉树的编号放入对应下标。

- **完全二叉树**：下标能直接反映关系——$i$ 的左孩子 $2i$、右孩子 $2i+1$、双亲 $\lfloor i/2\rfloor$；$2i\le n$ 则有左孩子；$i>\lfloor n/2\rfloor$ 是叶子。
- **普通二叉树**：必须先按完全二叉树的规则补虚结点再编号，会**浪费大量空间**；最坏情况（高 $h$ 的斜树）也要 $2^h-1$ 个单元。

> [!warning] 结论（选择题爱考）
> **二叉树的顺序存储只适合完全二叉树**，实际中很少用；0 基下标时对应关系变为左孩子 $2i+1$、右孩子 $2i+2$、双亲 $\lfloor(i-1)/2\rfloor$（视频留作练习）。

### 5.2 链式存储（二叉链表，★必背）

```c
typedef struct BiTNode {
    ElemType data;               // 数据域
    struct BiTNode *lchild, *rchild;  // 左右孩子指针
} BiTNode, *BiTree;
```

- $n$ 个结点有 $2n$ 个指针域，其中指向孩子的指针对应 $n-1$ 条边，因此**空链域 = $2n-(n-1)=n+1$**——这 $n+1$ 个空链域正是后面线索二叉树的基础。
- 找孩子方便、**找双亲要遍历整棵树**；若常需逆向找双亲，可加 `parent` 指针变成**三叉链表**（考研默认不带 parent）。

## 六、二叉树的先中后序遍历（视频043，★★★★★ 本章之魂）

### 6.1 三种遍历规则

| 遍历 | 顺序 | 别名 |
|---|---|---|
| 先序 | **根** → 左子树 → 右子树 | 先根遍历 NLR |
| 中序 | 左子树 → **根** → 右子树 | 中根遍历 LNR |
| 后序 | 左子树 → 右子树 → **根** | 后根遍历 LRN |

递归代码（三兄弟，只换 visit 位置）：

```c
void PreOrder(BiTree T) {          // 先序
    if(T != NULL) {
        visit(T);
        PreOrder(T->lchild);
        PreOrder(T->rchild);
    }
}
void InOrder(BiTree T) {           // 中序：把visit放中间
    if(T != NULL) {
        InOrder(T->lchild);
        visit(T);
        InOrder(T->rchild);
    }
}
void PostOrder(BiTree T) {         // 后序：把visit放最后
    if(T != NULL) {
        PostOrder(T->lchild);
        PostOrder(T->rchild);
        visit(T);
    }
}
```

### 6.2 手算方法（考试要又快又准）

**方法一：分支结点逐层展开法。**遇到分支结点就按对应规则把它"展开"成下一层（根左右/左根右/左右根）。

**方法二：路径法。**脑补出空结点，从根出发画一条"始终优先往左走、走到尽头就回退"的路径，**每个结点会被路过 3 次**：

- 先序 = 第 1 次路过就访问；
- 中序 = 第 2 次路过才访问；
- 后序 = 第 3 次（最后一次）路过才访问。

> [!tip] 表达式树应用（真题考过）
> 对算术表达式的语法分析树做先序/中序/后序遍历，分别得到**前缀 / 中缀 / 后缀表达式**；中缀表达式输出时要自己补括号。

### 6.3 复杂度与变化

- 时间 O(n)；**空间 O(h)**（递归调用栈，斜树时退化为 O(n)）。
- 遍历是万金油：**求深度**（后序：`depth = max(左深,右深)+1`）、求结点数、求叶子数、判断平衡、复制树……都是三种遍历的变种。**凡结果依赖左右子树"先算出来"的，用后序**。

## 七、二叉树的层次遍历（视频044，★★★★）

用**辅助队列**，从根开始一层层访问：

```
1. 根结点入队
2. 循环：队不空时——
   出队一个结点 p，访问 p
   若 p 有左孩子则左孩子入队
   若 p 有右孩子则右孩子入队
```

> [!note] 要点
> - 入队的是**结点指针**而非结点本身，省空间；
> - 用**链队列**（树的大小未知）；
> - 层次遍历又叫**广度优先遍历**（BFS）；先/中/后序属于**深度优先遍历**（DFS）。

## 八、由遍历序列构造二叉树（视频045，★★★★★）

### 8.1 关键结论（选择/大题都考）

> **仅一种遍历序列不能唯一确定二叉树**（同一序列可对应多种形态）。
> **先序+中序 / 后序+中序 / 层序+中序 都能唯一确定**；**先序+后序不能唯一确定**（反例：只有左孩子的树 vs 只有右孩子的树，先序都是 AB、后序都是 BA）。

所以：**必须有中序**。原因是中序能告诉你"根在哪，左右子树各有哪些结点"。

### 8.2 构造方法（以先序+中序为例）

1. 先序**第一个**结点是根；
2. 在中序里找到根，**根的左边 = 左子树中序、右边 = 右子树中序**；
3. 用左子树结点个数切分先序，得到左右子树的先序；
4. 递归构造左右子树。

后序+中序：后序**最后一个**是根，其余步骤相同。层序+中序：层序第一个是根，然后按层序逐层确定左右子树的根（注意：若根在中序里左边为空，说明左子树为空，层序下一个结点是右子树根）。

> [!warning] 易错
> 遍历序列中**相邻**的两个字符**不代表父子关系**，只能靠"根 + 中序划分"来确定。

## 九、线索二叉树的概念（视频046，★★★★ 概念+手算）

### 9.1 为什么要线索化

普通二叉树有两个痛点：
1. 只能**从根出发**遍历，给定任意结点指针无法从中途往后遍历；
2. 找某结点的**前驱/后继**必须重新完整遍历一次。

解决：利用 $n+1$ 个空链域，让**空的左指针指向前驱、空的右指针指向后继**（这种指针叫**线索**），并增加两个标志位区分：

```c
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;        // 0=孩子，1=线索
} ThreadNode, *ThreadTree;
```

### 9.2 三种线索二叉树

按"用哪种遍历序列定义前驱后继"分：

- **中序线索二叉树**：按中序序列，前驱/后继用中序定义；
- **先序线索二叉树**：按先序序列；
- **后序线索二叉树**：按后序序列。

手算线索化：先写出遍历序列、给每个结点标上访问序号，然后把空链域连到对应前驱/后继（首结点前驱为空、尾结点后继为空，指向 NULL）。

> [!warning] 审题
> 问"某结点的前驱/后继"必须先说清是**中序前驱、先序后继**还是后序的——三种定义完全不同。

## 十、二叉树的线索化（视频047，★★★★ 代码重点）

### 10.1 中序线索化

本质就是**中序遍历**，一边遍历一边把空链域改线索；用一个 `pre` 指针记录"当前访问结点的前驱"（王道教材用**引用参数** `pre` 传递，效果等同全局变量）：

```c
void InThread(ThreadTree &p, ThreadNode *&pre) {
    if(p == NULL) return;
    InThread(p->lchild, pre);            // 先线索化左子树
    if(p->lchild == NULL) {              // 左孩子为空
        p->lchild = pre;                 //   左指针指向前驱
        p->ltag = 1;
    }
    if(pre != NULL && pre->rchild == NULL) {  // pre的右孩子为空
        pre->rchild = p;                 //   pre的右指针指向当前结点（p是pre的后继）
        pre->rtag = 1;
    }
    pre = p;                             // 更新pre
    InThread(p->rchild, pre);            // 再线索化右子树
}

void CreateInThread(ThreadTree T) {
    ThreadNode *pre = NULL;
    if(T != NULL) {                      // 空树直接返回
        InThread(T, pre);
        pre->rchild = NULL;              // 最后一个结点的右指针置空
        pre->rtag = 1;                   //   无需判断：中序最后一个结点必无右孩子
    }
}
```

> [!note] 为什么最后一个结点可以直接 `pre->rchild=NULL`？
> 中序遍历顺序是"左根右"，若最后访问的结点还有右孩子，右孩子必在其后被访问，矛盾。所以**中序/后序最后一个被访问的结点必无右孩子**；先序则不一定。

### 10.2 先序线索化：注意"爱的魔力转圈圈"

先序线索化时，某结点的左指针一旦变成前驱线索，再递归左子树就会**回到前驱、死循环**。解决办法：**递归左子树前检查 `ltag==0`**：

```c
void PreThread(ThreadTree &p, ThreadNode *&pre) {
    if(p == NULL) return;
    // 访问根（线索化根）……
    if(p->ltag == 0)                     // ★★★ 只有左指针真是孩子时才递归
        PreThread(p->lchild, pre);
    PreThread(p->rchild, pre);
}
```

### 10.3 后序线索化

先左、再右、后根，访问根时左右子树都已处理完，**不存在转圈问题**。

> [!tip] 王道教材写法与"中序遍历"的对应关系
> `InThread` 函数里"左子 → 中间处理根 → 右子"三部分，就是中序遍历的骨架；`pre` 用引用参数是为了让修改对外层可见。

## 十一、在线索二叉树中找前驱/后继（视频048，★★★★ 需能推导）

### 11.1 中序线索二叉树（找前驱找后继都行）

**找中序后继**：
- `rtag==1`：右指针就是后继线索，直接取；
- `rtag==0`：有右孩子，后继 = **右子树中最左下角的结点**（右子树中序第一个结点）。

**找中序前驱**：
- `ltag==1`：左指针就是前驱线索；
- `ltag==0`：有左孩子，前驱 = **左子树中最右下角的结点**（左子树中序最后一个结点）。

因此中序线索树**既能从任意结点正向遍历、也能逆向遍历**，且不需要递归（空间 O(1)）。

### 11.2 先序线索二叉树（只能方便找后继）

**找先序后继**：
- `rtag==1`：直接取右线索；
- `rtag==0`：**有左孩子则后继=左孩子；无左孩子则后继=右孩子**（先序"根左右"：根之后要么左孩子要么右孩子）。

**找先序前驱**：左右子树里全是它的后继，**普通二叉链表找不到前驱**——只能重新完整先序遍历，或用**三叉链表**（有双亲指针）分情况：
- p 是父的左孩子 → 前驱=父；
- p 是父的右孩子且左兄弟为空 → 前驱=父；
- p 是父的右孩子且左兄弟非空 → 前驱=左兄弟子树中**先序最后访问**的结点（从该子树根出发，有右先走右、无右走左，走到最底层）；
- p 是根 → 无前驱。

### 11.3 后序线索二叉树（只能方便找前驱）

**找后序前驱**：
- `ltag==1`：直接取左线索；
- `ltag==0`：有右孩子则前驱=右孩子；无右孩子则前驱=左孩子（后序"左右根"，p 之前要么右孩子要么左孩子）。

**找后序后继**：左右子树里全是它的前驱，普通二叉链表找不到——重新遍历或三叉链表分情况：
- p 是父的右孩子 → 后继=父；
- p 是父的左孩子且右兄弟为空 → 后继=父；
- p 是父的左孩子且右兄弟非空 → 后继=右兄弟子树中**后序最先访问**的结点（从该子树根出发，有左先走左、无左走右，走到最底层）；
- p 是根 → 无后继。

### 11.4 总结表（★记结论）

| 线索树类型 | 找后继 | 找前驱 |
|---|---|---|
| 中序线索 | ✅ 方便（线索或右子树最左下） | ✅ 方便（线索或左子树最右下） |
| 先序线索 | ✅ 方便（左孩子/右孩子） | ❌ 需三叉链表或重新遍历 |
| 后序线索 | ❌ 需三叉链表或重新遍历 | ✅ 方便（右孩子/左孩子） |

## 十二、树的存储结构（视频049，★★★）

### 12.1 双亲表示法（顺序存储）

数组元素：`data + parent(双亲下标)`，**根的双亲记为 -1**。

- 找双亲 **O(1)**，找孩子要**遍历整个数组 O(n)**；
- 适合"找父亲多、找孩子少"的场景——**并查集**就用它。

```c
#define MAX_TREE_SIZE 100
typedef struct {          // 树的结点定义
    ElemType data;
    int parent;           // 双亲在数组中的下标
} PTNode;
typedef struct {          // 树的类型定义
    PTNode nodes[MAX_TREE_SIZE];
    int n;                // 结点数
} PTree;
```

也可直接存储森林（多棵树根都记为 -1）。

### 12.2 孩子表示法（顺序+链式）

数组存结点（data + 孩子链表头指针），每个结点的孩子编号挂成链表。

- 找孩子方便、找双亲麻烦；
- 适合"找孩子多"的场景（如客服电话服务流程树）。

### 12.3 孩子兄弟表示法（纯链式，★最常用）

```c
typedef struct CSNode {
    ElemType data;
    struct CSNode *firstChild, *nextSibling;  // 第一个孩子 / 右兄弟
} CSNode, *CSTree;
```

- 左指针 = **第一个孩子**，右指针 = **下一个兄弟**；
- **存储形态和二叉树一模一样**（就是二叉链表），是"树/森林 ↔ 二叉树"转换的基础；
- 既能存树也能存森林（森林的树根之间视为**平级兄弟**，用右指针串起来）。

## 十三、树、森林与二叉树的转换（视频050，★★★★ 选择必考）

口诀：**左孩子、右兄弟**。

### 13.1 树 → 二叉树

1. 先画根结点；
2. **按树的层序**依次处理每个结点：把它所有孩子**用右指针串成"糖葫芦"**，再把**第一个孩子挂到该结点的左指针**下。

### 13.2 森林 → 二叉树

1. 先把森林中**所有树的根用右指针串起来**（它们是平级兄弟）；
2. 再按森林的层序，用同样的"右串糖葫芦、左挂第一个孩子"处理每个结点。

### 13.3 二叉树 → 树/森林

1. 先画出根（若是森林，先把根结点及右链整串拆下来，每棵右链上的结点是一棵树的根）；
2. **按层序**恢复每个结点的孩子：该结点的**左孩子及其右链整串**拆下来，分别作为它的孩子。

> [!warning] 做题建议
> 视频强调：转换时**严格按层序**逐个结点处理，不要东一个西一个，才不容易乱。层序顺序 = 树/森林原本的层序。

## 十四、树和森林的遍历（视频051，★★★ 记对应关系）

### 14.1 树的三种遍历

- **先根遍历**：先访问根，再依次先根遍历每棵子树（深度优先）；
- **后根遍历**：先后根遍历每棵子树，最后访问根（深度优先）；
- **层次遍历**：队列辅助，广度优先。

### 14.2 与二叉树遍历的等价关系（★★★ 选择题直接考）

| 树的遍历 | 对应二叉树遍历 | 森林遍历 | 对应二叉树遍历 |
|---|---|---|---|
| 先根遍历 | **先序遍历** | 先序遍历 | **先序遍历** |
| 后根遍历 | **中序遍历** | 中序遍历 | **中序遍历** |
| 层次遍历 | — | — | — |

> [!tip] 做题技巧
> 森林的先序/中序序列 = 依次对每棵树做先根/后根遍历后拼接；更快的办法：**先把森林转成二叉树再对二叉树遍历**，两个序列自动对齐。

## 十五、哈夫曼树与哈夫曼编码（视频052，★★★★）

### 15.1 基本概念

- **结点的权**：给结点赋一个有意义的数值（如出现频率）；
- **结点的带权路径长度** = 根到该结点的路径长度（边数）× 该结点权值；
- **树的带权路径长度 WPL** = **所有叶子结点**的带权路径长度之和：

$$
WPL=\sum_{i=1}^{n}w_i l_i
$$

- **哈夫曼树（最优二叉树）**：含给定 $n$ 个带权叶子的所有二叉树中 **WPL 最小**的那棵。

### 15.2 构造算法（贪心）

每次从当前森林中**选两个权值最小的树合并**，新根权值 = 二者之和，重复 $n-1$ 次，直到只剩一棵树。

**性质（★必记）**：
1. $n$ 个叶子 → 共 $2n-1$ 个结点（每次合并新增 1 个分支结点）；
2. **没有度为 1 的结点**；
3. 权值越小的叶子离根**越远**；
4. **哈夫曼树不唯一**（两个最小权谁左谁右、相等时选哪个都行），但 **WPL 唯一且最小**；
5. WPL = **所有合并产生的非叶结点权值之和**（验算神器）。

### 15.3 哈夫曼编码（数据压缩）

- 字符作为**叶子**、出现频率作为**权值**构造哈夫曼树；
- 左分支编码 0、右分支编码 1（左右可互换）；
- 得到的是**前缀编码**：任何字符的编码都不是另一个字符编码的前缀 → **解码无歧义**；
- 属于**可变长度编码**：高频字符码长短、低频字符码长长，使平均码长最小。

> [!warning] 区分
> 哈夫曼编码保证**平均码长最短**，但不保证每个字符的码长都最短（低频字符码长可能比等长编码还长）。

## 十六、并查集（视频053，★★★★★ 2022新增考点，近年热门）

### 16.1 逻辑结构与存储

- 逻辑上是**集合**：元素被划分为若干个**互不相交的子集**；
- 用**双亲表示法**（一个 int 数组）存储：`S[i]` 存 i 的双亲下标，**根结点存负数**（绝对值 = 集合大小，或存 -1）。

```c
int S[MAXSIZE];   // 并查集：双亲表示法
```

### 16.2 基本操作（★代码必须会写）

**初始化**：每个元素自成集合，全置 -1。

```c
void Initial(int S[]) {
    for(int i = 0; i < MAXSIZE; i++)
        S[i] = -1;            // 各自独立成集
}
```

**查 Find**：一路向上找根（根的特征是 `S[i]<0`）。

```c
int Find(int S[], int x) {    // 返回 x 所在集合的根
    while(S[x] >= 0)
        x = S[x];             // 沿着双亲链上溯
    return x;                 // S[x]<0，x 就是根
}
```

**并 Union**：把一个集合的根挂到另一个集合的根下面。

```c
void Union(int S[], int root1, int root2) {
    if(root1 == root2) return;       // 已在同一集合
    S[root2] = root1;                // root2 的根指向 root1
}
```

复杂度：Union O(1)；**Find 最坏 O(n)**（树退化成链时）；n-1 次 Union 建树最坏 O(n²)。

### 16.3 优化一：Union 按大小（小树并入大树）

根结点存**负的集合大小**（如 -6 表示该集合 6 个结点）。合并时**把小树并入大树**，并更新大树根的大小：

```c
void Union_Optimized(int S[], int root1, int root2) {
    if(root1 == root2) return;
    if(S[root2] > S[root1]) {        // 负值比较：root2 比 root1 更小
        S[root1] += S[root2];        // 累加结点总数
        S[root2] = root1;            // 小树根指向大树根
    } else {
        S[root2] += S[root1];
        S[root1] = root2;
    }
}
```

效果：树高 ≤ $\lceil\log_2 n\rceil$，**Find 最坏 O(log n)**。

## 十七、并查集的进一步优化：路径压缩（视频054，★★★★★）

### 17.1 思路

Find 一次后，把**查找路径上的所有结点直接挂到根**下面，下次查找路径就变短了（"压缩路径"）：

```c
int Find_Compress(int S[], int x) {   // 带路径压缩的查找
    int root = x;
    while(S[root] >= 0)               // 第一步：先找到根
        root = S[root];
    while(x != root) {                // 第二步：沿途结点全部挂到根下
        int t = S[x];
        S[x] = root;
        x = t;
    }
    return root;
}
```

### 17.2 复杂度总结（★背结论）

| 方案 | 单次 Find 最坏 | 合并 n 个元素总时间 |
|---|---|---|
| 朴素（无优化） | O(n) | O(n²) |
| 按大小合并 | O(log n) | O(n log n) |
| 按大小合并 + 路径压缩 | O(α(n))，α 增长极慢（常见 n 时 α≤4，近似常数） | O(n α(n)) |

> [!note] 应用预告
> 第6章 **Kruskal 算法用并查集判环**；并查集擅长"动态合并 + 判断连通"，**不支持拆分集合**。

### 18.4 易错点清单

1. **二叉树 ≠ 度为 2 的有序树**（允许空、允许度 1）。
2. 完全二叉树**叶子不都在同一层**；度 1 结点至多 1 个且**只能是左孩子**。
3. 先序+后序**不能**唯一确定二叉树；**必须有中序**。
4. 遍历序列里的"相邻"不代表父子关系。
5. 线索指针**不能当孩子递归**（先序线索化转圈）；递归前查 `ltag`。
6. 中序/后序线索树最后一个结点**必无右孩子**，可放心置 NULL；先序的最后一个不一定。
7. **WPL 只算叶子**的带权路径长度；哈夫曼树无度 1 结点；WPL = 合并权值之和。
8. 并查集根存**负数**，比较大小是 `S[root2] > S[root1]`（负值越大集合越小），符号别搞反。
9. 树转二叉树的"糖葫芦"：**右指针串兄弟、左指针挂第一个孩子**，方向别反。
10. 树的度 ≠ 树的叉：度为 3 的树至少 m+1 个结点，三叉树可以为空。

## 旧版补充：题型训练与复习资料

### 典型题型与解题方法

1. **结点计数**：同时写结点总数与边数方程，利用度数求和。
2. **由序列构树**：先定根，再在中序中切左右区间；每层区间边界必须一致。
3. **遍历算法**：先写空树边界；求高度、结点数、平衡性适合后序，因为结果依赖左右子树。
4. **线索题**：先确定遍历次序，再判断指针是孩子还是线索。
5. **哈夫曼题**：每轮只取当前森林中两个最小权；用合并权值和复核 WPL。
6. **并查集题**：画双亲数组变化，区分路径压缩发生于 `Find`，按大小合并发生于 `Union`。


### 完整例题与逐步解答

#### 例 1：由先序和中序构造二叉树

已知先序序列为 `ABDECFG`，中序序列为 `DBEAFCG`，求二叉树并写出后序序列。

> [!success]- 展开完整答案
> 先序第一个字符 A 是根。在中序中，A 左侧 `DBE` 属于左子树，右侧 `FCG` 属于右子树。
>
> - 左子树先序取接下来的 3 个字符 `BDE`，根为 B；中序 `DBE` 中 B 左为 D、右为 E。
> - 右子树先序为 `CFG`，根为 C；中序 `FCG` 中 C 左为 F、右为 G。
>
> ```text
>         A
>       /   \
>      B     C
>     / \   / \
>    D   E F   G
> ```
>
> 后序按“左—右—根”得到
>
> $$
> \boxed{DEBFGCA}.
> $$
>
> 每一层都必须在同一个中序区间内切分左右子树；不能只凭两个序列中字符相邻就断言父子关系。

#### 例 2：哈夫曼树与 WPL

有 4 个叶结点，权值为 5、7、10、15。构造哈夫曼树并求 WPL。

> [!success]- 展开完整答案
> 每轮选择当前森林中两个最小权：
>
> 1. $5+7=12$；
> 2. $10+12=22$；
> 3. $15+22=37$。
>
> 哈夫曼树的 WPL 等于所有非叶结点合并权值之和：
>
> $$
> WPL=12+22+37=\boxed{71}.
> $$
>
> 也可按叶子深度验算：15 深度 1，10 深度 2，5 和 7 深度 3，
>
> $$
> 15\times1+10\times2+5\times3+7\times3=71.
> $$
>
> 左右孩子的 0/1 编码可以交换，不影响码长和 WPL；哈夫曼编码是前缀编码。

#### 例 3：并查集按大小合并与路径压缩

元素 0～3 初始各自成集，双亲数组根结点用负数记录集合大小。依次执行 `Union(0,1)`、`Union(2,3)`、`Union(0,2)`，再执行 `Find(3)`，数组如何变化？

> [!success]- 展开完整答案
> 初态：
>
> ```text
> [-1, -1, -1, -1]
> ```
>
> 合并 0、1 后让 0 为根：`[-2,0,-1,-1]`。合并 2、3 后：`[-2,0,-2,2]`。再合并两个大小均为 2 的集合，若规定 0 为新根：
>
> ```text
> [-4, 0, 0, 2]
> ```
>
> 执行 `Find(3)` 时路径为 $3\to2\to0$，路径压缩后把 3 直接挂到 0：
>
> ```text
> [-4, 0, 0, 0]
> ```
>
> 按大小合并在 `Union` 时限制树高，路径压缩在 `Find` 返回时缩短以后查询路径；两种优化作用阶段不同。


### 做题识别顺序

1. 性质题同时写结点数、边数和度数和方程。
2. 构树题先由先序/后序定根，再在中序中切左右区间。
3. 递归算法根据“结果依赖谁”选遍历：依赖左右子树的高度、平衡、结点数多用后序。
4. 线索题先确定遍历序列，再根据标志位区分孩子指针和线索。
5. 哈夫曼每轮重新从当前森林取两个最小权；并查集合并前先 Find 根。


### 一页记忆

$$
\boxed{
n_0=n_2+1,\qquad
\text{二叉链表空链域}=n+1
}
$$

$$
\boxed{WPL=\sum w_i l_i=\text{各次合并权值之和}}
$$

- 先序+中序、后序+中序通常能唯一确定二叉树；仅先序+后序通常不能。
- 完全二叉树顺序存储中，0 基下标 $i$ 的孩子为 $2i+1,2i+2$。
- 中序线索后继：有右孩子则找右子树最左结点；无右孩子则沿后继线索直达。
- 并查集配合按秩/大小合并和路径压缩，均摊代价近似常数。


### 易错点

- 二叉树不是度为 2 的有序树，两者对空子树位置的定义不同。
- 完全二叉树的叶结点不一定都在同一层。
- 遍历序列中的“相邻”通常不代表父子关系。
- 线索指针不可当孩子递归，否则可能形成循环。
- 哈夫曼编码的左右 0/1 可交换；计算 WPL 看权与路径长度。
- 并查集数组中的负值若表示大小，比较合并方向时符号容易反。

### 自测问题

1. 为什么二叉链表有 $n+1$ 个空链域？
2. 哪两类遍历序列通常能唯一确定二叉树？
3. 中序线索树如何找某结点后继？
4. 哈夫曼树为何没有度为 1 的结点？
5. 路径压缩与按秩合并分别优化哪个操作阶段？

> [!question]- 自测问题参考答案
> 1. 每个结点有两个孩子指针，共 $2n$ 个链域；非空孩子指针对应树的 $n-1$ 条边，所以空链域为 $2n-(n-1)=n+1$。
> 2. 结点互异时，先序+中序或后序+中序通常能唯一构树；层序+中序也可在明确规则下构造。仅先序+后序一般不唯一。
> 3. 若该结点有右孩子，后继是右子树中最左结点；若无右孩子且右标志表示线索，则右指针直接指向中序后继。
> 4. 构造时所有内部结点都来自“两棵最小权子树合并”，因此一旦成为内部结点就恰有两个孩子，不会出现度为 1。
> 5. 按秩/大小合并在 Union 时让矮树挂到高树，控制未来高度；路径压缩在 Find 时把访问路径结点直接连到根，优化后续查找。
